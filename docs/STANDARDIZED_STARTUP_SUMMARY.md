## 🎯 解决的问题

### 问题1: 端口不一致
**之前**:
- `db-tunnel-persistent.sh` 使用端口 5433
- `ssh-tunnel-manager.sh` 使用端口 15433
- 导致混乱和冲突

**现在**:
- 统一使用端口 5433
- 所有脚本配置一致

### 问题2: 脚本重复和混乱
**之前**:
- 4个不同的隧道脚本
- 2个不同的dev-start脚本
- 功能重叠，不知道用哪个

**现在**:
- 清晰的推荐: `tunnel.sh` 和 `dev.sh`
- 旧脚本标记为历史版本
- 文档中明确说明

### 问题3: 使用复杂
**之前**:
- 需要记住长路径
- 需要手动启动多个服务
- 没有统一的文档

**现在**:
- 简单的别名: `dev`, `tunnel-start`
- 一键启动: `dev`
- 完整的文档和快速参考


自动完成:

自动检查:

## 🚀 快速开始

### 首次使用（3步）

```bash
# 1. 安装别名
source scripts/setup-dev-aliases.sh
dev-install
source ~/.zshrc

# 2. 启动开发环境
dev

# 3. 查看状态
dev-status
```

### 日常使用

```bash
# 早上: 启动
dev

# 工作中: 查看日志
log-backend
log-frontend

# 晚上: 停止
dev-stop
```

## 📊 对比

### 之前的启动流程

```bash
# 1. 启动隧道（需要记住脚本路径和参数）
~/scripts/db-tunnel-persistent.sh start
# 或
./scripts/ssh-tunnel-manager.sh start

# 2. 等待隧道建立
sleep 5

# 3. 手动测试数据库连接
PGPASSWORD='...' psql -h localhost -p 5433 -U ai_prod_user -d ai_project_prod -c "SELECT 1"

# 4. 启动后端（需要cd到正确目录）
cd backend
go run main.go &

# 5. 启动前端（需要再cd）
cd ../frontend
npm start &

# 总共需要5-6个命令，容易出错
```

### 现在的启动流程

```bash
# 一个命令搞定
dev

# 就这么简单！
```

## 🎨 架构设计

### 分层架构

```
用户层 (Aliases)
    ↓
入口层 (dev.sh)
    ↓
服务层 (tunnel.sh, backend, frontend)
    ↓
基础设施层 (SSH, PostgreSQL, HTTP)
```

### 统一配置

所有脚本使用统一的配置:

```bash
# 端口
TUNNEL_PORT=5433
BACKEND_PORT=8080
FRONTEND_PORT=3000

# 日志
LOG_DIR=/tmp
LOG_PREFIX=ai-proj-

# 数据库
DB_HOST=localhost
DB_PORT=5433
DB_NAME=ai_project_prod
DB_USER=ai_prod_user
```
