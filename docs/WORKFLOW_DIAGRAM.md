## 🔒 分支保护机制

```
┌───────────────────────────────────────────────────────┐

│  ✅ 所有CI检查必须通过                                  │
```

## 🚨 冲突解决流程

```
开发者A                    main分支                    开发者B
   │                         │                          │
   ├─ commit A1              │                          │
   │  (修改 user.go)         │                          ├─ commit B1
   │                         │                          │  (修改 user.go)
   │                         │                          │
   ├─ commit A2              │                          ├─ commit B2
   │                         │                          │
   ├─ push ──────────────────┼─────────────────────────►│ push (失败!)
   │                         │                          │
   ├─ PR合并 ────────────────┤                          │
   │                    ┌────▼────┐                     │
   │                    │  main   │                     │
   │                    │ +A1+A2  │                     │
   │                    └─────────┘                     │
   │                         │                          │
   │                         │                          ├─ 拉取最新main
   │                         │                          │  git fetch origin
   │                         │                          │
   │                         │                          ├─ 尝试rebase
   │                         │                          │  git rebase main
   │                         │                          │
   │                         │                      ┌───▼────┐
   │                         │                      │ 冲突！  │
   │                         │                      │user.go │
   │                         │                      └───┬────┘
   │                         │                          │
   │                         │                          ├─ 手动解决冲突
   │                         │                          │  编辑 user.go
   │                         │                          │  选择保留的代码
   │                         │                          │
   │                         │                          ├─ 标记已解决
   │                         │                          │  git add user.go
   │                         │                          │  git rebase --continue
   │                         │                          │
   │                         │                          ├─ push
   │                         │                          │  git push --force
   │                         │                          │
   │                         │ ◄────────────────────────┤ PR合并
   │                         │                          │
   └─────────────────────────┴──────────────────────────┘
```

## 🎨 最佳实践流程

```
功能开发
   │
   ├─ 小而频繁的提交 (每小时1-2次)
   │  ✅ 功能模块化
   │  ✅ 易于回滚
   │  ✅ 减少冲突
   │
   ├─ 定期同步main (每天至少1次)
   │  ✅ 避免长期分离
   │  ✅ 早发现冲突
   │  ✅ 减少合并难度
   │
   ├─ PR保持小而聚焦 (< 500行)
   │  ✅ 易于审查
   │  ✅ 快速反馈
   │  ✅ 降低风险
   │
   ├─ 充分的代码审查
   │  ✅ 功能性检查
   │  ✅ 代码质量
   │  ✅ 安全性审查
   │  ✅ 性能考量
   │
   └─ 自动化测试和部署
      ✅ CI自动运行
      ✅ 部署自动化
      ✅ 回滚机制
```

---

**关键原则**：
- 🚫 **永远不要直接推送到main**
- 📝 **小而频繁的PR**
- 👀 **认真审查每个PR**
- 💬 **保持良好沟通**
- ✅ **CI必须通过**
