## 🎯 系统概述

需求管理系统帮助团队规范化地收集、评审、跟踪和实现产品需求,确保需求从提出到实现的全流程可追溯。

### 核心功能

- ✅ **需求提交** - 快速创建和提交产品需求
- ✅ **评审流程** - 规范的需求评审和批准流程
- ✅ **协作讨论** - 通过评论@同事进行需求讨论
- ✅ **任务转换** - 将批准的需求转换为开发任务
- ✅ **进度跟踪** - 实时查看需求状态和统计数据

### 需求生命周期

```
草稿 → 待评审 → 已批准 → 开发中 → 已实现 → 已归档
    ↓
   已拒绝
```

### 用户角色和权限

| 角色 | 权限 |
|------|------|
| 普通用户 | 创建需求、评论、查看 |
| 评审者 | 批准/拒绝需求 |
| 项目经理 | 转换任务、分配资源 |
| 管理员 | 所有权限 |

## ✍️ 创建需求

### 第一步: 点击"新建需求"按钮

在需求列表页面,点击右上角的"+ 新建需求"按钮。

### 第二步: 填写需求基本信息

#### 必填字段

1. **需求标题** (1-200字符)
   - ✅ 清晰简洁: "添加用户登录功能"
   - ❌ 模糊不清: "登录"

2. **需求描述** (详细说明)
   - 背景: 为什么需要这个功能?
   - 目标: 要解决什么问题?
   - 范围: 包含哪些功能点?

   示例:
   ```
   背景:
   当前系统没有用户认证功能,任何人都可以直接访问。

   目标:
   实现安全的用户登录系统,保护用户数据。

   范围:
   1. 用户名密码登录
   2. 记住登录状态
   3. 找回密码功能
   ```

3. **所属项目**
   - 从下拉列表选择项目
   - 如果没有合适的项目,联系项目经理创建

#### 推荐填写字段

4. **优先级**
   - 🔴 紧急 (urgent): 影响主流程,必须立即处理
   - 🟠 高 (high): 重要功能,优先排期
   - 🟡 中 (medium): 常规需求
   - 🟢 低 (low): 优化类需求

5. **需求分类**
   - 🆕 新功能 (feature)
   - 🐛 Bug修复 (bug)
   - ⚡ 功能改进 (improvement)

6. **商业价值**
   ```
   示例:
   - 提升用户留存率10%
   - 减少客服咨询量30%
   - 满足合规要求
   ```

7. **预期成果**
   ```
   示例:
   - 用户可以使用用户名和密码安全登录
   - 支持记住登录状态7天
   - 提供友好的错误提示
   ```

8. **验收标准**
   ```
   示例:
   ✅ 输入正确凭据可以成功登录
   ✅ 错误凭据显示明确的错误信息
   ✅ 支持找回密码功能
   ✅ 登录态保持7天
   ✅ 3次密码错误后锁定账号5分钟
   ```

9. **截止日期** (可选)
   - 选择期望的完成日期
   - 帮助团队合理安排优先级

### 第三步: 保存草稿

- 点击"保存草稿" - 需求保存为草稿状态,可以稍后继续编辑
- 点击"提交评审" - 直接提交给评审者

### 最佳实践

✅ **DO (推荐做法)**:
- 标题言简意赅,一句话说清楚
- 描述详细具体,包含背景和目标
- 附上参考资料(竞品截图、PRD文档等)
- 明确验收标准,避免理解偏差
- 填写商业价值,帮助优先级决策

❌ **DON'T (不推荐)**:
- 标题太模糊: "优化一下"
- 描述太简单: "加个功能"
- 没有验收标准
- 优先级随意标注
- 缺少商业价值说明

## ✅ 需求审批流程

### 提交评审

1. **确认需求完整**
   - 检查必填字段是否填写完整
   - 验收标准是否明确
   - 附件是否已上传

2. **点击"提交评审"按钮**
   - 需求状态变为"待评审"
   - 系统自动通知评审者
   - 提交后无法直接编辑,需要撤回

### 等待评审

- 评审者会收到通知
- 通常1-2个工作日内完成评审
- 可以在评论区催办或补充说明

### 评审者操作

#### 批准需求

1. 评审者点击"批准"按钮
2. 填写批准意见(可选)
   ```
   示例:
   - 需求清晰,可以开始开发
   - 建议在开发中注意XXX问题
   ```
3. 需求状态变为"已批准"

#### 拒绝需求

1. 评审者点击"拒绝"按钮
2. **必须**填写拒绝原因
   ```
   示例:
   - 需求描述不够详细,请补充XXX信息
   - 验收标准不明确
   - 与现有功能XX冲突,需要重新设计
   - 商业价值不清晰
   ```
3. 需求状态变为"已拒绝"
4. 提交者收到通知,可以修改后重新提交

### 撤回需求

如果需求提交后发现需要修改:

1. 点击"撤回"按钮
2. 需求状态恢复为"草稿"
3. 可以继续编辑
4. 编辑完成后重新提交评审

### 审批流程图

```
[提交者创建需求]
      ↓
  [保存为草稿] ←──────┐
      ↓              │
  [提交评审] ──→ [可撤回]
      ↓
 [评审者审核]
      ├──批准──→ [已批准] → [转为任务]
      │
      └──拒绝──→ [已拒绝] → [修改重提]
```

## 💬 评论和协作

### 发表评论

1. **在需求详情页找到评论区**
   - 滚动到页面下方
   - 或点击"评论"标签

2. **输入评论内容**
   - 一般评论: 提出想法和建议
   - 提问: 询问需求细节
   - 批准意见: 评审通过的理由
   - 拒绝意见: 评审不通过的原因

3. **@提及同事**
   - 输入 `@` 符号
   - 从下拉列表选择同事
   - 被@的同事会收到通知

   示例:
   ```
   @张三 请帮忙确认一下这个需求的技术可行性
   @李四 @王五 这个需求涉及你们的模块,请review
   ```

4. **选择评论类型**
   - 💬 一般评论
   - ❓ 提问
   - 💡 建议
   - ✅ 批准意见
   - ❌ 拒绝意见

5. **点击"发表评论"**

### 回复评论

1. 点击评论下方的"回复"按钮
2. 输入回复内容
3. 点击"提交"

### 编辑和删除评论

- **编辑**: 点击自己评论右上角的"编辑"按钮
- **删除**: 点击自己评论右上角的"删除"按钮
- 注意: 只能编辑/删除自己的评论

### 置顶重要评论

管理员或需求提交者可以置顶重要评论:

1. 点击评论右上角的"⋮"菜单
2. 选择"置顶"
3. 置顶的评论显示在评论列表顶部

### 查看@我的评论

1. 点击顶部导航栏的通知图标🔔
2. 选择"需求提及"
3. 查看所有@我的评论
4. 点击可以直接跳转到相关需求

### 评论最佳实践

✅ **DO**:
- 评论清晰具体
- @相关人员确保他们看到
- 及时回复他人的提问
- 保持专业和礼貌

❌ **DON'T**:
- 发表无意义的评论
- 在评论中讨论无关话题
- 忽略他人的@提及
- 使用不恰当的语言

## 🔄 转换为任务

### 何时转换为任务?

需求状态为"已批准"时,即可转换为开发任务。

### 转换流程

#### 方式一: 直接转换 (推荐)

1. **打开已批准的需求**
2. **点击"转为任务"按钮**
3. **填写任务信息**:

   | 字段 | 说明 | 示例 |
   |------|------|------|
   | 任务标题 | 默认使用需求标题 | 实现用户登录功能 |
   | 任务描述 | 默认引用需求描述 | 根据需求#123实现... |
   | 所属项目 | 与需求保持一致 | 电商平台 |
   | 优先级 | 继承需求优先级 | 高 |
   | 负责人 | 选择开发负责人 | @张三 (后端工程师) |
   | 截止日期 | 设置开发deadline | 2025-12-15 |
   | 创建子任务 | 推荐勾选 | ✅ 是 |

4. **勾选"创建子任务"**

   系统会自动建议子任务:
   ```
   ✅ 实现登录API接口
   ✅ 实现登录前端页面
   ✅ 编写单元测试
   ✅ 更新用户文档
   ```

   你可以:
   - 修改建议的子任务
   - 删除不需要的
   - 添加新的子任务

5. **勾选"关联需求"**
   - 自动建立需求-任务关联
   - 在需求详情页可以看到关联的任务
   - 在任务详情页可以看到来源需求

6. **点击"确认转换"**

   转换成功后:
   - 创建主任务和子任务
   - 需求状态变更为"开发中"
   - 负责人收到任务通知
   - 需求和任务建立关联

#### 方式二: 手动关联

如果任务已经存在,可以手动关联:

1. **打开需求详情页**
2. **找到"关联任务"区域**
3. **点击"+ 关联现有任务"**
4. **搜索并选择任务**
   - 输入任务ID或标题搜索
   - 从列表中选择任务
5. **选择关联类型**:
   - 🔄 转换而来: 从需求直接转换的任务
   - 🔗 手动关联: 手动关联的相关任务
   - 📎 相关任务: 与需求相关但非直接转换
6. **点击"确认关联"**

### 转换后的跟踪

#### 查看任务进度

1. **在需求详情页**:
   - 滚动到"关联任务"区域
   - 查看任务状态和进度
   - 点击任务标题跳转到任务详情

2. **任务状态同步**:
   ```
   任务状态         →  需求状态
   ────────────────────────────
   待办/进行中      →  开发中
   已完成          →  待验收
   已验收          →  已实现
   ```

#### 验收需求

当关联的所有任务都完成后:

1. 测试人员进行测试
2. 产品经理验收功能
3. 确认满足验收标准
4. 将需求状态更新为"已实现"

### 转换最佳实践

✅ **DO**:
- 转换前再次确认需求已批准
- 合理拆分子任务
- 分配给合适的开发人员
- 设置合理的截止日期
- 保持需求和任务的描述同步

❌ **DON'T**:
- 转换未批准的需求
- 子任务拆分过细或过粗
- 忘记设置负责人
- 截止日期不合理
- 任务和需求描述不一致

## ❓ 常见问题

### Q1: 需求提交后发现信息填错了怎么办?

**A**: 有两种方法:
1. **撤回需求**: 如果还在"待评审"状态,点击"撤回"按钮,修改后重新提交
2. **评论说明**: 在评论中@评审者说明需要修改的内容,等待拒绝后重新提交

### Q2: 紧急需求如何快速审批?

**A**:
1. 将优先级设为"紧急"
2. 在评论中@评审者并说明紧急原因
3. 或直接联系评审者进行审批
4. 系统会优先推送紧急需求的通知

### Q3: 一个需求可以转换为多个任务吗?

**A**: 可以。
1. 第一次转换时勾选"创建子任务"
2. 或转换后再手动关联其他相关任务
3. 所有关联任务都会显示在需求详情页

### Q4: 需求被拒绝后怎么办?

**A**:
1. 查看拒绝原因(在评论或拒绝记录中)
2. 根据原因修改需求内容
3. 在评论中@评审者说明修改内容
4. 重新提交评审

### Q5: 如何搜索需求?

**A**: 支持多种搜索方式:
- **关键词搜索**: 在搜索框输入标题或描述关键词
- **ID搜索**: 输入需求ID (如: #123)
- **高级筛选**: 组合使用状态、优先级、项目等筛选条件

### Q6: 评论可以删除吗?

**A**:
- 可以删除自己的评论
- 管理员可以删除任何评论
- 批准/拒绝意见建议不要删除,保留审批记录

### Q7: 需求转任务后还能修改吗?

**A**:
- 需求内容可以修改,但会记录修改历史
- 建议在评论中说明修改原因
- 重大修改建议知会关联任务的负责人

### Q8: 如何批量操作需求?

**A**: 管理员权限支持批量操作:
1. 勾选需求列表中的多个需求
2. 点击"批量操作"下拉菜单
3. 选择操作: 批量删除、批量更新状态等

### Q9: 附件大小有限制吗?

**A**:
- 单个文件: 最大10MB
- 总附件大小: 最大50MB
- 支持格式: 图片、PDF、Word、Excel等
- 不支持: 可执行文件(.exe, .sh等)

### Q10: 收不到通知怎么办?

**A**: 检查以下设置:
1. **个人设置** > **通知偏好**
2. 确认邮箱地址正确
3. 检查邮箱垃圾箱
4. 联系系统管理员检查邮件服务配置
