# 工作笔记 · 任务 #418（项目ID：1）

一句话目标：为项目任务提供“后代节点（Descendants）”查询能力与前端“懒加载任务树”展示，让复杂任务的分解、推进与验收可视化、可追踪，并最终在甘特图中按里程碑与依赖关系呈现。


## 背景与动机
- 现状问题：
  - 子任务只支持一层列表，难以洞察深层级结构与整体进度。
  - 手动展开/折叠成本高，页面首次加载冗重，体验不佳。
  - 文档/验收信息分散，缺乏统一视图和“可交付物对齐”的里程碑标注。
- 机会与目标：
  - 后端提供深度受控、可分页的后代查询接口，前端采用懒加载树形视图，做到“用多少，取多少”。
  - 将任务分支职责清晰映射到子任务树，配合甘特图实现端到端进度与验收闭环。


## 目标与非目标
- 目标（Must）：
  1) 后端提供 GET /api/v1/projects/:id/tasks/:taskId/descendants，支持 depth/limit，输出拍平结构（含 level、has_children、排序等）。
  2) 前端在任务详情页接入“子任务树”懒加载组件，节点点击才请求下一层，展示基础元信息与快捷操作。
  3) 为查询性能建立必要索引；仓库层/集成测试覆盖典型/边界场景。
  4) 将关键里程碑与依赖映射到甘特图，辅助任务验收与回归。
- 非目标（Out of Scope）：
  - 跨项目任务合并视图（本期仅在单项目内工作）。
  - 权限与审计模型大改（本期遵循既有模型，后续迭代）。


## 产出与影响范围
- 最终产出（可交付物）：
  - 后端接口：任务后代查询（分页/深度），拍平节点结构，has_children 标记，稳定排序。
  - 数据库：tasks(parent_id)、tasks(parent_id, sort_order, id) 索引迁移脚本。
  - 前端：TaskDetailDescendantsTree 懒加载树组件、服务调用与任务详情页集成；节点元信息 Tooltip 与“更多”菜单。
  - 测试：仓库层查询测试、集成测试（含深度/分页/无子节点等边界）；前端基本交互自测。
  - 文档：本工作笔记、接口/路由说明、变更记录。
- 影响系统/模块：
  - backend models/database/handlers/routes
  - frontend services/components/pages/styles
- 涉及数据/表/索引：
  - 表：tasks
  - 索引：parent_id、(parent_id, sort_order, id)


## 验收标准（Definition of Done）
- 接口正确性
  - 场景1：Given 存在多层子任务树 When depth=1 请求 Then 返回仅一层子节点，level=1，父节点的 has_children 正确。
  - 场景2：Given 深层结构 When depth=3、limit=N Then 返回不超过 N 条拍平节点，level ∈ [1,3]，排序按 sort_order,id 稳定。
  - 场景3：Given 叶子节点 When 请求后代 Then data 为空数组，has_children=false。
  - 场景4：Given 非法/缺失任务 When 请求 Then 返回 404/错误体结构符合规范。
  - 场景5：鉴权 When 未携带认证头 Then 返回 401，错误码 UNAUTHORIZED。
- 前端交互
  - 场景6：首次打开详情页 When 展示子任务树 Then 仅请求 depth=1，显示一级子节点与“可展开”提示。
  - 场景7：点击可展开节点 When 展开 Then 延迟加载下一层，缓存结果，重复展开/收起不重复请求。
  - 场景8：节点元信息 Tooltip When 悬浮 Then 展示负责人名片、截止日期（含逾期/临近提示）、优先级、小计数与进度。
  - 场景9：更多操作菜单 When 点击 Then 可“打开详情/打开文档/编辑任务/新建子任务”，导航正确。
  - 场景10：状态展示中文化，风格与详情页一致。
- 性能与稳定
  - 场景11：P95 延迟 depth≤2 且 limit≤200 时 < 150ms（后端链路，测试环境参考值）；
           depth=3 时 < 250ms（参考值，受数据量影响）。
  - 场景12：索引生效，Explain 计划无全表扫描（大库验收）。
- 测试与质量
  - 场景13：仓库层/集成测试通过，覆盖典型/边界；前端构建通过，无阻塞型 TS 错误。
  - 场景14：错误处理与空态展示合理（401/404/空列表）。

## 执行流程（建议）
1) 契约阶段：定义拍平结构字段（id、parent_id、level、has_children、sort_order、状态等），过评审。
2) 后端阶段：仓库实现与 Handler/路由对接 → 加索引迁移 → 本地 Explain 验证。
3) 测试阶段：仓库/集成用例覆盖深度/分页/空态/鉴权等。
4) 前端阶段：服务方法（axios）、懒加载树、Tooltip 与更多菜单、错误与空态。
5) 集成阶段：任务详情页替换旧列表；与文档 Tab、甘特图联动验证。
6) 收尾：文档与变更记录、监控/日志校验、回归用例沉淀。


## 时序与依赖
- 依赖：DB 迁移需先执行；接口稳定后前端联调；鉴权中间件沿用既有模型。
- 风险与缓解：
  - 大量子树导致延迟 ↑ → 懒加载+分页+索引；必要时降级深度或限制 limit。
  - 跨项目引用 → 先仅在单项目内展示，后续评估跨项目视图。
