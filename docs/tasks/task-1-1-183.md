⏺ 任务编辑时选择父任务的产品需求与开发计划

  📋 产品需求总结

  🎯 核心问题

  当前任务编辑功能在父任务选择方面存在功能缺失和设计缺陷：
  - TaskModal（弹窗）支持父任务修改，但体验差
  - TaskEditPage（独立页面）完全缺失父任务修改功能
  - 现有选择框无法处理大数据量和复杂筛选需求

  📝 详细需求

  1. 功能完整性需求

  - R1.1 TaskEditPage必须支持父任务修改功能
  - R1.2 两种编辑方式（弹窗/独立页面）功能必须一致
  - R1.3 支持清除父任务（设为根任务）

  2. 数据筛选需求

  - R2.1 只能选择当前项目内的任务作为父任务
  - R2.2 父任务层级不能≥3（防止创建4级任务）
  - R2.3 防止循环依赖（递归检查所有后代任务）
  - R2.4 过滤当前编辑的任务本身

  3. 性能与用户体验需求

  - R3.1 支持关键词搜索（服务端搜索，非客户端过滤）
  - R3.2 支持分页加载（处理大项目的大量任务）
  - R3.3 任务列表按层级结构展示
  - R3.4 显示任务层级关系、状态、ID等关键信息
  - R3.5 响应式设计，适配移动端

  4. 交互设计需求

  - R4.1 采用弹窗选择器替代下拉选择框
  - R4.2 树形结构展示，支持展开/折叠
  - R4.3 搜索结果高亮显示
  - R4.4 提供面包屑导航显示任务路径
  - R4.5 加载状态和空状态友好提示

⏺ 🛠 技术要求分析

  后端API扩展

  // 新增父任务搜索API
  GET /api/v1/projects/:id/tasks/search-parents
  Query Parameters:
  - keyword: string (搜索关键词)
  - page: number (页码)
  - page_size: number (每页大小)
  - exclude_task_id: number (排除的任务ID)
  - max_level: number (最大层级限制，默认2)

  Response:
  {
    data: Task[],
    total: number,
    page: number,
    page_size: number,
    has_more: boolean
  }

  前端组件架构

  // 新组件结构
  ├── TaskParentSelector.tsx          // 父任务选择器主组件
  ├── TaskParentSelectorModal.tsx     // 弹窗容器
  ├── TaskSearchInput.tsx             // 搜索输入框
  ├── TaskTreeList.tsx               // 树形任务列表
  ├── TaskTreeNode.tsx               // 单个任务节点
  └── hooks/
      ├── useTaskParentSearch.ts     // 父任务搜索hook
      ├── useTaskTreeData.ts         // 树形数据管理
      └── useParentValidation.ts     // 父任务验证逻辑

  核心技术点

  - 虚拟滚动：处理大量任务列表性能
  - 防抖搜索：优化搜索体验
  - 循环依赖检测：递归算法验证
  - 层级计算：动态层级限制

⏺ ⚖️ 工作量评估与优先级

  工作量评估

  | 阶段      | 工作量   | 关键风险      |
  |---------|-------|-----------|
  | Phase 1 | 2-3天  | 循环依赖算法复杂度 |
  | Phase 2 | 3-4天  | 树形组件交互复杂  |
  | Phase 3 | 2-3天  | 现有代码集成风险  |
  | Phase 4 | 1-2天  | 性能调优时间不确定 |
  | 总计      | 8-12天 | 中等复杂度项目   |

  优先级矩阵

  高影响 + 高紧急度 = P0 立即执行
  ├── TaskEditPage功能补全 (功能缺失)
  ├── 循环依赖验证算法 (数据安全)
  └── 核心搜索API (性能瓶颈)

  高影响 + 低紧急度 = P1 优先执行
  ├── 弹窗选择器UI组件
  ├── 树形展示优化
  └── 移动端适配

  低影响 + 高紧急度 = P2 后续执行
  ├── 动画效果
  └── 高级搜索筛选
