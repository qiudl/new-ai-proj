## 问题描述

### 问题1: 环境标识重复显示
- **现象**: 页面头部同时显示"开发环境"和"生产环境"两个标签
- **影响**: 用户无法正确识别当前运行环境
- **严重程度**: 中等（影响用户体验）

### 问题2: API请求域名错误
- **现象**: 前端向 `http://localhost:8080/api/v1/*` 发送请求
- **预期**: 应该向 `https://proj.joylodging.com/api/v1/*` 发送请求
- **影响范围**:
  - 第一阶段：所有API端点
  - 第二阶段（第一次修复后）：仅 `/user/timer/current` 端点
- **严重程度**: 高（导致功能完全不可用）

## 根本原因分析

### 问题1根因
**文件**: `.env.production`
**原因**: 缺少 `REACT_APP_LOCAL_DEV=false` 环境变量

**代码逻辑**（Layout.tsx 第568-616行）:
```typescript
{/* 开发环境标识 */}
{process.env.REACT_APP_LOCAL_DEV === 'true' && (
  <Tag color="orange" style={environmentBadgeStyle}>
    开发环境
  </Tag>
)}

{/* 生产环境标识 */}
{process.env.REACT_APP_ENV === 'production' && (
  <Tag color="red" style={environmentBadgeStyle}>
    生产环境
  </Tag>
)}
```

由于 `.env.production` 中：
- `REACT_APP_ENV=production` ✅ 存在 → 显示"生产环境"
- `REACT_APP_LOCAL_DEV` ❌ 未定义 → 默认被视为真值 → 显示"开发环境"

### 问题2根因
**文件**: `src/utils/URLBuilder.ts`
**原因**: 硬编码的localhost fallback逻辑

**原始代码**（第65-96行）:
```typescript
private detectBaseUrlWithPrefix(apiPrefix: string, debug: boolean): string {
  const candidates = [
    process.env.REACT_APP_API_URL,
    process.env.REACT_APP_API_BASE_URL,
    process.env.REACT_APP_BASE_URL,
    'http://localhost:8080'  // ❌ 问题：硬编码的localhost
  ];

  for (const candidate of candidates) {
    if (candidate && candidate.trim()) {
      // ... 处理逻辑
      return cleanCandidate;
    }
  }

  return 'http://localhost:8080';  // ❌ 问题：最终fallback也是localhost
}
```

**问题分析**:
1. 如果环境变量未正确加载（例如构建时环境变量未传入）
2. 所有候选URL为空或undefined
3. 函数返回硬编码的 `http://localhost:8080`
4. SSE Timer Service使用URLBuilder构建请求URL
5. 导致生产环境请求localhost而不是生产域名

### 修复1: 环境变量配置

**文件**: `.env.production`

```diff
+# 明确声明非本地开发环境
+REACT_APP_LOCAL_DEV=false

# 禁用Source Map以减小构建体积和提高安全性

TSC_COMPILE_ON_ERROR=true
```

### 修复2: URLBuilder智能Fallback

**文件**: `src/utils/URLBuilder.ts`
**修改内容**:
```diff
private detectBaseUrlWithPrefix(apiPrefix: string, debug: boolean): string {
  // 按优先级检查环境变量
  const candidates = [
    process.env.REACT_APP_API_URL,
    process.env.REACT_APP_API_BASE_URL,
    process.env.REACT_APP_BASE_URL,
-   'http://localhost:8080'  // 移除硬编码localhost
  ];

  for (const candidate of candidates) {
    if (candidate && candidate.trim()) {
      const cleanCandidate = candidate.trim();

      // 如果URL已经包含API前缀，返回不含前缀的部分
      if (cleanCandidate.includes(apiPrefix)) {
        const baseUrl = cleanCandidate.replace(new RegExp(apiPrefix.replace('/', '\\\\/') + '.*$'), '');
        return baseUrl;
      }

      return cleanCandidate;
    }
  }

-  return 'http://localhost:8080';
+  // 生产环境不应该fallback到localhost
+  // 使用当前域名作为fallback
+  if (typeof window !== 'undefined') {
+    const protocol = window.location.protocol;
+    const host = window.location.host;
+    return `${protocol}//${host}`;
+  }
+
+  return 'http://localhost:8080';
}
```

**优化说明**:
- ✅ 优先使用环境变量配置的API URL
- ✅ 如果环境变量缺失，动态使用当前域名（`window.location`）
- ✅ 仅在非浏览器环境（如SSR）才使用localhost
- ✅ 确保生产环境永远不会错误地请求localhost

## 技术细节

### React环境变量工作原理

1. **构建时注入**:
   - 环境变量在 `npm run build` 时被webpack处理
   - 所有 `process.env.REACT_APP_*` 被替换为实际值
   - 生成的JavaScript文件中包含硬编码的值

2. **运行时不可更改**:
   - Docker容器中的环境变量**不会**影响已构建的前端代码
   - 必须重新构建才能应用新的环境变量

3. **验证方法**:
   ```javascript
   // 在浏览器控制台中无法访问
   console.log(process.env.REACT_APP_API_URL); // undefined

   // 但代码中已被替换为实际值
   // 构建前: process.env.REACT_APP_API_URL
   // 构建后: "https://proj.joylodging.com/api/v1"
   ```

### URLBuilder Fallback优先级

修复后的fallback优先级:
1. **REACT_APP_API_URL** (最高优先级)
2. **REACT_APP_API_BASE_URL**
3. **REACT_APP_BASE_URL**
4. **window.location** (浏览器环境动态检测)
5. **localhost:8080** (仅非浏览器环境，如Node.js SSR)

### 浏览器缓存机制

**为什么需要强制刷新**:
- **Service Worker**: 可能缓存旧版JavaScript
- **HTTP缓存**: 浏览器缓存静态资源（JS/CSS）
- **CDN缓存**: 如果使用CDN，可能需要等待TTL过期

**清除缓存的完整方法**:
```
1. 硬刷新 (Ctrl+Shift+R / Cmd+Shift+R)
2. 如果还有问题，手动清除:
   - Chrome: Settings → Privacy → Clear browsing data
   - 选择 "Cached images and files"
3. 检查Service Worker:
   - chrome://serviceworker-internals/
   - 找到proj.joylodging.com相关的worker
   - 点击 "Unregister"
```

```javascript
requiredEnvVars.forEach(varName => {

    console.error(`❌ Missing required environment variable: ${varName}`);
    process.exit(1);
  }
});

console.log('✅ All required environment variables are set');
```
