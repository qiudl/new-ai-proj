🔧 Mermaid React.StrictMode修复验证

🐛 问题根本原因确认

核心问题：React.StrictMode在开发环境下故意执行useEffect两次
导致现象：第一次执行设置renderingRef.current=true，第二次执行直接return，渲染永远不完成
解决策略：检测到重复执行时重置渲染状态，允许正常渲染流程

🔧 修复实施详情

修复前的问题代码：

useEffect(() => {
  const renderMermaid = async () => {
    // ❌ 问题：StrictMode第二次执行时直接退出
    if (!ref.current || renderingRef.current) return;
    
    setIsLoading(true);
    setError(null);
    renderingRef.current = true;
    // ... 渲染逻辑
  };
  renderMermaid();
}, [chart, id]);

修复后的代码：

useEffect(() => {
  const renderMermaid = async () => {
    if (!ref.current) return;
    
    // ✅ 修复：StrictMode重复执行时重置状态
    if (renderingRef.current) {
      console.log('🔄 React.StrictMode检测到重复执行，重置渲染状态');
      renderingRef.current = false;
      if (timeoutRef.current) {
        clearTimeout(timeoutRef.current);
        timeoutRef.current = null;
      }
    }
    
    setIsLoading(true);
    setError(null);
    renderingRef.current = true;
    // ... 渲染逻辑
  };
  renderMermaid();
}, [chart, id]);

🔬 技术细节

React.StrictMode的影响机制：

  • 开发环境：StrictMode故意执行两次副作用函数（useEffect）
  • 目的：帮助开发者发现副作用函数中的问题
  • 影响：不正确处理重复执行会导致状态混乱
  • 生产环境：StrictMode不会执行两次，但代码应该兼容

修复策略的设计思路：

  • 检测重复：通过renderingRef.current判断是否为重复执行
  • 状态重置：清理之前的渲染状态和定时器
  • 继续渲染：重置后正常执行渲染流程
  • 超时优化：简化超时检查逻辑，提高可靠性
