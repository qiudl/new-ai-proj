
**执行流程**:
1. 检查依赖工具 (psql, pg_dump, gzip)
2. 验证SQL文件存在

5. 创建完整备份
6. 用户确认
7. 执行SQL脚本
8. 验证迁移结果
9. 生成日志文件

**日志文件**:

- 错误日志: `logs/migrations/migration_error_TIMESTAMP.log`

### 5. 备份和恢复脚本 ✅

**文件**: `backend/scripts/backup_restore_requirements.sh`

**备份功能**:

#### 5.1 完整数据库备份
```bash
./backup_restore_requirements.sh backup full
```
- 备份整个数据库
- SQL格式，gzip压缩
- 适合灾难恢复

#### 5.2 需求表备份
```bash
./backup_restore_requirements.sh backup requirements
```
- 仅备份需求管理的4个表
- 包括表结构和数据
- 更快速，文件更小

#### 5.3 数据备份
```bash
./backup_restore_requirements.sh backup data
```
- 仅备份数据，不含表结构
- 适合数据迁移

#### 5.4 自定义格式备份
```bash
./backup_restore_requirements.sh backup custom
```
- PostgreSQL自定义格式
- 支持并行恢复
- 最大压缩率

**恢复功能**:

#### 5.5 完整恢复
```bash
./backup_restore_requirements.sh restore full backup_file.sql.gz
```

#### 5.6 需求表恢复
```bash
./backup_restore_requirements.sh restore requirements backup_file.sql.gz
```
- 恢复前自动创建安全备份
- 验证恢复后的数据

#### 5.7 自定义格式恢复
```bash
./backup_restore_requirements.sh restore custom backup_file.dump
```

**维护功能**:

#### 5.8 列出备份
```bash
./backup_restore_requirements.sh list
```
- 显示所有可用备份
- 备份类型、大小、时间戳

#### 5.9 清理旧备份
```bash
./backup_restore_requirements.sh cleanup
```
- 删除30天前的备份
- 可通过RETENTION_DAYS环境变量配置

**安全特性**:
- 恢复前强制创建安全备份
- 多次确认机制
- 自动解压gzip文件
- 恢复后数据验证

## 使用示例

### 场景1: 首次部署到生产环境

```bash
# 1. 设置环境变量
export DB_HOST="prod-db.example.com"
export DB_NAME="ai_project_prod"
export DB_USER="prod_user"
export DB_PASSWORD="secure_password"

# 2. 验证连接
cd /path/to/backend
./scripts/migrate_requirement_system.sh verify

# 3. 执行迁移（包含自动备份）
./scripts/migrate_requirement_system.sh up

# 4. 验证迁移
./scripts/verify_requirement_migration.sh

# 5. 查看日志
tail -f logs/migrations/migration_*.log
```

### 场景2: 仅创建备份

```bash
# 完整备份
./scripts/backup_restore_requirements.sh backup full

# 仅需求表
./scripts/backup_restore_requirements.sh backup requirements

# 列出所有备份
./scripts/backup_restore_requirements.sh list
```

### 场景3: 紧急回滚

```bash
# 1. 确认问题需要回滚
./scripts/verify_requirement_migration.sh

# 2. 执行回滚（会创建安全备份）
./scripts/migrate_requirement_system.sh down

# 3. 验证回滚结果
psql -d ai_project_db -c "
SELECT table_name FROM information_schema.tables
WHERE table_name LIKE 'requirement%';
"
```

### 场景4: 从备份恢复

```bash
# 1. 列出可用备份
./scripts/backup_restore_requirements.sh list

# 2. 恢复指定备份
./scripts/backup_restore_requirements.sh restore requirements \
  backups/requirements/requirements_backup_20251106_120000.sql.gz

# 3. 验证恢复的数据
./scripts/verify_requirement_migration.sh
```
