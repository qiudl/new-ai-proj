# 任务：将任务详情页的子任务列表扩展为能显示孙任务的层级结构

## 背景与目标
- 当前任务详情页仅展示一层子任务，无法直观看到孙任务及更深层级。
- 目标：在任务详情页支持多层级（至少支持到孙任务，优先设计成可扩展的任意层级），提供折叠/展开、批量操作、性能可用性保障。

## 范围（In/Out）
- In：后端数据结构/查询、接口返回、前端树形渲染、交互（展开/折叠/懒加载）、基本性能优化、权限与可见性处理、测试与文档。
- Out：跨项目关联的任务汇总树（另行规划）。

## 关键需求与验收标准
1. 层级展示：默认显示到子任务层，支持按需展开到孙任务及更深层级。
2. 交互：
   - 节点可展开/折叠，状态持久（页面期内或用户首选项）。
   - 提供一键全部展开/折叠。
3. 性能：
   - 打开详情页时首屏渲染 < 200ms（前端渲染时间，mock 环境）。
   - 请求时间在 95 百分位 < 400ms（1000 子节点以内）。
   - 大数据量（>2k 节点）时支持懒加载或分页/虚拟列表。
4. 权限：用户仅能看到有权限的任务及其可见的子树。
5. 可用性：空态、加载态、错误态明确。

## 技术方案概述
### 数据与后端
- 现状假设：任务表具备 parent_id 字段，形成树。
- 查询方案：采用 PostgreSQL 递归 CTE（WITH RECURSIVE）按任务ID获取后代节点；根据需要限制深度（默认 2-3 层）并支持“继续加载更多”。
- 性能：
  - 建议索引：parent_id、(parent_id, sort_order)。
  - 如未来需更大规模与频繁树计算，可评估闭包表（closure table）或物化路径（ltree）。
- 返回结构：
  - 方案A：后端返回平铺数组 + parent_id，前端组装为树（简洁通用）。
  - 方案B：后端直接返回嵌套树（减少前端组装成本）。
  - 推荐：默认A，并提供 depthLimit、cursor/offset 支持。
- 环境要求：
  - 开发与测试优先使用 Docker 的 Postgres（遵循用户规则）；生产使用 Postgres。

### 前端渲染
- 基于树组件实现（可复用现有列表逻辑，增加树形缩进与展开状态）。
- 支持：
  - 展开/折叠图标；
  - 逐层懒加载（点击展开时再请求该子树）；
  - 虚拟滚动（当节点总数较大）；
  - 节点行展示与当前单层一致（标题、状态、负责人、进度、操作等）。

### 交互与状态
- 展开状态在页面会话内缓存；可选：持久化到 localStorage/服务端用户偏好。
- 提供全部展开/折叠按钮；
- 键盘可访问性（a11y）：Tab、Enter、Space 操作节点展开。

### 安全与权限
- 后端在查询层做权限过滤，避免越权。
- 接口需在返回中标识是否仍有隐藏子节点（因权限或分页被截断）。

### 监控与可观测性
- 为后端查询新增指标（qps、p95、错误率）。
- 前端埋点：展开/折叠点击、加载耗时、错误。

## API 草案
GET /api/tasks/{id}/descendants?depth=2&limit=200&cursor=xxx
- 请求参数：
  - depth：最大层级深度（缺省 2）。
  - limit/cursor：分页或分层加载。
- 响应：
  - data：平铺数组（id, parent_id, ...）；
  - page_info：{ has_more, next_cursor }；
  - meta：{ max_depth_reached, truncated }。

## 里程碑与分工建议
- M1：需求确认与低保真原型
- M2：后端接口与权限处理
- M3：前端树组件与懒加载
- M4：联调与性能优化
- M5：测试、文档与灰度发布

## 测试计划
- 后端：递归 CTE 单元测试、权限过滤测试、性能基准（小/中/大规模）。
- 前端：组件单测（展开/折叠/懒加载/虚拟化）、集成测试、可访问性测试。
- E2E：典型用户路径覆盖，含无权限节点与大树场景。

## 风险与应对
- 大树性能：采用懒加载 + 虚拟列表；必要时评估闭包表/物化路径。
- 权限复杂度：在 SQL 层做过滤；响应包含截断提示。
- 交互复杂：先小步上线（仅两层），再逐步放开深度。

## 验收清单
- 支持展开至孙任务；
- 大任务树交互流畅（p95<400ms）；
- 权限正确；
- 有稳定的监控与测试覆盖。
