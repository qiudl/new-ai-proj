# Phase 2.2: 需求关联已有任务功能 - 实现文档

## 任务概述

实现需求与已有任务的关联管理功能，包括手动关联、解除关联、查询关联关系等核心功能。

## 实现内容

### 1. 数据层 (Repository Layer)

#### 1.1 RequirementTaskRepository接口

**文件**: `backend/database/requirement_task_repository.go` (新建, 567行)

实现了完整的需求-任务关联数据访问层：

**核心方法**:
- `Create(ctx, link)` - 创建关联，内置去重检查
- `GetByID(ctx, id)` - 获取单个关联详情（包含JOIN查询）
- `Delete(ctx, id)` - 删除关联
- `DeleteByRequirementAndTask(ctx, reqID, taskID)` - 按需求和任务ID删除
- `GetByRequirementID(ctx, reqID)` - 获取需求的所有关联任务
- `GetByTaskID(ctx, taskID)` - 获取任务的所有关联需求
- `GetByRequirementAndTask(ctx, reqID, taskID)` - 检查特定关联是否存在
- `List(ctx, filters)` - 分页查询，支持多维度过滤
- `Exists(ctx, reqID, taskID)` - 快速检查关联是否存在
- `CountByRequirement(ctx, reqID)` - 统计需求的关联任务数
- `CountByTask(ctx, taskID)` - 统计任务的关联需求数

**技术特点**:
- 使用JOIN查询获取关联数据（需求标题、任务标题、关联人用户名）
- 在Create时自动进行去重检查
- 支持灵活的分页和过滤
- 完整的错误处理

### 2. 业务逻辑层 (Handler Layer)

#### 2.1 RequirementTaskHandler

**文件**: `backend/handlers/requirement_task_handler.go` (新建, 316行)

实现了4个核心API处理方法：

##### LinkTaskToRequirement
- **路由**: `POST /api/v1/requirements/:id/tasks`
- **功能**: 创建手动或相关类型的需求-任务关联
- **验证**:
  - 需求是否存在
  - 任务是否存在
  - 防止重复关联
- **默认**: link_type默认为"manual"
- **返回**: 包含完整关联信息的响应

##### UnlinkTaskFromRequirement  
- **路由**: `DELETE /api/v1/requirements/:id/tasks/:task_id`
- **功能**: 删除需求-任务关联
- **保护**: 不允许删除"converted"类型的关联（转换产生的关联）
- **验证**:
  - 关联是否存在
  - 关联类型检查

##### GetRequirementTasks
- **路由**: `GET /api/v1/requirements/:id/tasks`
- **功能**: 获取需求的所有关联任务
- **支持**:
  - 分页（page, page_size）
  - 按link_type过滤
- **返回**: 分页的任务列表及关联信息

##### GetTaskRequirements
- **路由**: `GET /api/v1/tasks/:id/requirements`
- **功能**: 获取任务的所有关联需求
- **支持**:
  - 分页（page, page_size）
  - 按link_type过滤
- **返回**: 分页的需求列表及关联信息

## 关联类型说明

系统支持三种关联类型（RequirementTaskLinkType）：

1. **manual** - 手动关联
   - 由用户主动创建的关联
   - 可以被删除

2. **converted** - 需求转任务
   - 通过"需求转任务"功能自动创建
   - 受保护，不能被删除
   - 确保需求和转换任务的关系不被破坏

3. **related** - 相关任务
   - 标记为相关但非直接转换的关联
   - 可以被删除

## 业务规则

### 1. 去重规则
- 同一需求和任务只能有一个关联记录
- Create时自动检查，存在则返回错误

### 2. 删除保护
- `converted`类型的关联不允许删除
- 这确保了需求转任务的历史记录完整性

### 3. 权限控制
- 所有操作都需要JWT认证
- 依赖系统现有的权限中间件

### 4. 级联影响
- 删除需求或任务时，相关联的记录会被自动清理（通过数据库外键）
- 需求状态变更（如撤回）不影响已有关联

## 技术亮点

### 1. 智能去重
Repository层的Create方法内置了Exists检查，防止重复关联：
```go
exists, err := r.Exists(ctx, link.RequirementID, link.TaskID)
if exists {
    return nil, fmt.Errorf("该需求和任务已存在关联关系")
}
```

### 2. JOIN查询优化
查询时通过JOIN获取关联数据，减少N+1查询问题：
```sql
SELECT 
    rt.*,
    r.title as requirement_title,
    r.status as requirement_status,
    t.title as task_title,
    t.status as task_status,
    u.username as linker_username
FROM requirement_tasks rt
LEFT JOIN requirements r ON rt.requirement_id = r.id
LEFT JOIN tasks t ON rt.task_id = t.id
LEFT JOIN users u ON rt.linked_by = u.id
```

### 3. 类型安全
使用常量枚举定义link_type：
```go
const (
    RequirementTaskLinkManual    RequirementTaskLinkType = "manual"
    RequirementTaskLinkConverted RequirementTaskLinkType = "converted"
    RequirementTaskLinkRelated   RequirementTaskLinkType = "related"
)
```

### 4. 灵活过滤
List方法支持多条件组合查询：
```go
type RequirementTaskFilters struct {

```
