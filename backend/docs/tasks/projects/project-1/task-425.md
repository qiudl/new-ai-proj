# 重构方案：全部任务页面（UI/UX）

> 目标：提升信息可读性、交互效率与跨角色（执行者/管理者）使用体验，显著减少查找与操作任务的时间成本。

## 1. 设计原则
- 清晰层级：优先展示关键信息（标题、状态、负责人、截止时间、优先级）。
- 一致反馈：所有操作（筛选、排序、批量操作）均提供即时可逆反馈。
- 低认知负担：减少视觉噪点，使用约定俗成的图标与手势。
- 可访问性（a11y）：对比度 AA、键盘可达、屏幕阅读友好、焦点可见。
- 性能先行：首屏 < 1s、交互 < 100ms、虚拟化长列表。

## 2. 信息架构（IA）与布局
- 顶部工具栏：
  - 全局搜索（支持命令式搜索：`status:open assignee:me`）。
  - 关键筛选：状态、负责人、标签、优先级、项目、日期（创建/截止/更新）。
  - 视图切换：列表 / 看板 / 日历 / 洞察（分析）。
  - 批量操作入口：批量更新状态/负责人/标签/优先级/截止日期、合并任务。
- 主区域（可切换视图）：
  - 列表视图：紧凑型数据表（可配置列、保存视图、固定列、水平滚动）。
  - 看板视图：按状态/负责人/优先级分泳道，支持拖拽，列内排序与在列内新建。
  - 日历视图：周/月视图，拖拽调整日期，冲突高亮。
  - 洞察视图：逾期、工作量分布、SLA、周期时间、累计流图（CFD）。
- 右侧详情抽屉：点击任务在不离开列表的情况下展开详情（基本信息、描述、评论、子任务、活动日志、依赖关系、历史版本）。
- 底部状态条：选中计数、批量操作按钮、当前筛选摘要与清除一键。

## 3. 关键交互
- 即时筛选与保存视图：
  - 任意筛选组合可另存为“视图”（私有/共享），可设为默认。
  - 支持快捷键打开筛选（如 `f`）与搜索（`/`）。
- 内联编辑：
  - 列表单元格可直接编辑（标题、状态、负责人、优先级、日期、标签）。
  - 编辑后提供小型 toast + 撤销（5s）。
- 拖拽操作：
  - 看板列间拖动改变状态；列表按住拖动调整优先级序。
- 批量操作：
  - 多选行后出现批量条，可一次性改状态/负责人等，并显示影响范围。
- 空状态与错误：
  - 空列表提供“清晰下一步”（创建任务、清除筛选、导入）。
  - 错误卡片含重试、诊断信息（网络/权限）。

## 4. 可视表达与样式
- 色彩：状态采用色条+中性色背景；优先级用形状与颜色双编码。
- 排版：14px 基础字号、表头半粗、行高 40px 紧凑模式；可切换密度（舒适/紧凑）。
- 图标：有限、语义化；悬停显示二级操作（复制链接、关注、更多）。
- 徽标：逾期（红点+天数）、即将到期（橙条）、被阻塞（禁行标）。

## 5. 数据模型与字段建议
- 必备字段：id、title、status、assignee、priority、due_date、project、tags、updated_at。
- 扩展：parent_id、dependencies、estimate、actual、sla、custom_fields（JSON）。
- 排序：updated_at desc 为默认，支持多列排序与固定自定义排序。

## 6. 性能与技术实现
- 客户端：
  - 列表虚拟化（如 React Window/Virtualized），行内编辑乐观更新。
  - 请求合并与去抖（搜索 200ms debounce）。
  - 视图配置本地缓存 + 服务器持久化。
- 服务端：
  - 分页（游标优先）、筛选字段索引、批量写接口、变更订阅（WebSocket/SSE）。
- 监控：
  - 性能指标：TTFB、FCP、INP、LCP；交互失败率。
  - 埋点：筛选使用率、保存视图覆盖率、批量操作成功率。

## 7. 可访问性与国际化
- 键盘导航：Tab/Shift+Tab、Enter 编辑、Esc 取消、上下选择、Space 多选。
- ARIA：role=grid + aria-colindex/rowindex；可读状态与校验提示。
- 语言：i18n 文案抽取，日期/数字本地化。

## 8. 安全与权限
- 权限控制字段级与操作级（能否批量改负责人等）。
- 审计日志：批量操作与导入导出。

## 9. 迁移与发布计划
- Alpha（内部）：实现列表视图 + 详情抽屉 + 基本筛选与内联编辑。
- Beta：加入看板、日历、批量操作、保存视图。
- GA：洞察视图、导入导出、权限细化、完整埋点。
- 回滚策略：保留旧页面路径 `/tasks/legacy`，开关灰度。

## 10. 可交付物
- 低保真线框：关键视图与空状态。
- 高保真稿：主题、组件规范（按钮/输入/标签/表格）。
- 交互原型：主要流程（筛选、内联编辑、批量操作、拖拽）。
- 设计标注与组件库切片。

## 11. 层级父子任务（Tree）设计（新增）

### 11.1 目标与原则
- 以树形组织任务，支持无限层级；默认展开至 2〜3 层，降低视觉负担。
- 保持跨视图一致：列表、看板、日历、洞察均具备层级可视与操作一致性。
- 可控的级联：重要操作（状态、负责人、日期、优先级）提供清晰的级联开关与预览。
- 汇总可信：父任务自动展示进度/工时/逾期等聚合指标，可配置权重。

### 11.2 数据模型（Postgres 友好）
- 字段：
  - parent_id（nullable）
  - depth（int，小根为 0/1）
  - has_children（bool）
  - order_in_parent（int，用于同层排序）
  - path（text/ltree，物化路径，示例：`1.7.42`）
  - rollup_cache（jsonb：children_count、open_children、progress_percent 等）
- 索引：
  - btree(parent_id, order_in_parent)、btree(updated_at)、btree(status, priority)、btree(assignee)
  - 若启用 ltree：gist(path) 用于快速子树查询（生产环境 Postgres 推荐）
- 查询：
  - 子树：`WHERE path <@ '1.7'`（ltree）或 `WITH RECURSIVE` CTE（邻接表）
  - 祖先链：`WHERE '1.7.42' @> path`（ltree）或 CTE 反向递归
- 约束：防环校验（reparent 时检查不可把父设为自身后代）。
- 开发/测试：建议使用 Docker 的 Postgres（符合你的偏好）；生产使用 Postgres（符合生产规则）。

### 11.3 列表视图（TreeGrid）
- 视觉：
  - 行首展开/折叠图标（▸/▾），缩进体现层级；父行吸顶（sticky）便于上下文保持。
  - 父行展示聚合：已完成/总计子任务数、开放/阻塞计数、加权进度条、最早开始/最晚截止。
- 交互：
  - 键盘：Left 折叠 / Right 展开，Ctrl/Cmd+Right 展开整支，Shift+Space 选中子树。
  - 拖拽：
    - 同层重排（改变 order_in_parent）。
    - 拖到其它父节点上实现“改父级”（reparent）；提供预检与撤销。
  - 内联：标题/负责人/状态/日期/优先级可直接编辑；改父级可在详情抽屉中以选择器完成。
- 筛选语义：
  - 保持上下文：当命中子任务时，自动显示其祖先（以灰色弱化呈现），并标注“由筛选显示”。
  - 视图选项：
    - 仅叶子（隐藏含子项的父任务）；
    - 展示全部祖先（命中行以上的父级全部展开）；
    - 展示全部后代（命中父级时自动展开其全部子孙，限载 N 条以保护性能）。
- 排序模式：
  - 树内排序（层内排序，保持树结构）与全局排序（打平）可切换；默认树内排序。

### 11.4 看板视图（层级化）
- 表现：
  - 父卡片显示聚合指标与子任务计数；点击展开，子卡片以缩进或堆叠列表形态呈现。
  - 子卡片可独立拖拽变更状态；父卡片可拖拽跨列仅在“独立状态”模式下允许。
- 状态策略（可配置）：
  - 独立：父状态不随子变化；
  - 汇总：当所有子完成时父自动转为“已完成”；有任一子阻塞则父显示“被阻塞”徽标。

### 11.5 日历视图
- 父任务以跨度条（bar）覆盖最早开始-最晚截止区间；子任务作为嵌套条/标记显示。
- 拖动父任务日期时弹出级联选项：
  - 不级联；
  - 相对偏移（子任务日期整体平移 Δt）；
  - 仅调整未开始子任务。

### 11.6 详情抽屉（大纲面板）
- 大纲（Outline）分栏：树形结构快速定位与重排；支持拖拽改父级、创建兄弟/子任务、批量粘贴创建子任务。
- 依赖/被依赖可与层级并存，冲突时明确提示（层级≠依赖）。

### 11.7 批量与级联策略
- 批量操作（状态/负责人/优先级/标签/截止）：
  - 选项：仅当前、包含直接子级、包含全部后代；默认“仅当前”。
  - 预览影响范围与计数，支持撤销。
- 状态汇总与进度：
  - 进度=加权完成子任务数/总权重，权重默认使用 estimate，无估算则等权。
  - 父状态建议默认“独立”，提供项目级开关启用自动汇总完成。
- 删除与归档：
  - 删除父级时需确认：仅删除父任务（子上移到更高层）/删除整棵子树。

### 11.8 汇总与洞察
- 每个父级提供：open/blocked/done 计数、进度%、逾期数、累计预估/实际工时。
- 洞察视图可按层级汇总：
  - Epic/Feature/Story/Task 层级分布与完成趋势；
  - Epic 周期时间=首个子任务开始到最后一个子任务完成。

### 11.9 可访问性（a11y）
- 列表采用 role=treegrid，使用 aria-expanded、aria-level、aria-setsize/posinset 标注。
- 键盘完整支持：Home/End/上下移动、Left/Right 折叠展开、* 展开整支。
- 屏幕阅读器朗读“第 N 层/有 K 个子项/已展开/已折叠”等语义。

### 11.10 性能与技术实现
- 客户端：虚拟化树（仅渲染可见节点），增量加载子节点；缓存已展开分支；乐观 reparent。
- 接口：
  - GET /tasks/tree?root=…&depth=…（游标分页）
  - GET /tasks/{id}/children（分页）
  - 批量写：POST /tasks/batch-update，支持级联参数 cascade=none|children|descendants。
- 数据库（Postgres）：
  - 优先 ltree 物化路径或邻接表+CTE；维护 path/depth 的触发器；
  - 聚合缓存（rollup_cache）由触发器/后台任务维护，避免大子树实时计算；
  - 必要索引与 ANALYZE，保障筛选/排序性能。
- 环境：开发/测试使用 Docker 的 Postgres；生产使用 Postgres。

### 11.11 权限与安全
- 改父级与跨项目移动需具备相应权限；可限制将子任务 reparent 到无权限的项目。
- 审计记录：reparent、批量级联、删除子树等高风险操作。

### 11.12 迁移与发布
- 数据迁移：补齐 parent_id/path/depth，回填 rollup_cache；检测并阻断环。
- 功能灰度：先在列表视图启用树，随后扩展到看板/日历。
- 回滚：保留扁平视图与旧接口；reparent 产生的变更可审计回退。

### 11.13 验收标准（示例）
- 列表可展示 3 层以上层级并支持键盘折叠/展开；
- 看板可展开父卡片并独立拖拽子卡片；
- 父级进度在有估算时按加权统计且性能 <100ms；
- 改父级 1,000 节点规模下成功率 >99.9%，平均 <300ms；
- 级联更新前有影响范围预览，支持撤销。
