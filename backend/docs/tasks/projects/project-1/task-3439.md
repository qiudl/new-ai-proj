# Task #3439: Phase 3.3: RequirementList页面 - 需求列表和筛选

## 任务概述

实现需求管理系统的列表页面，包含完整的筛选功能、分页、排序和基本操作。

## 实现内容

### 1. 类型定义文件 (src/types/requirement.ts)

创建了完整的需求管理类型定义，包括：

**枚举类型**:
- `RequirementStatus`: 需求状态（草稿、待评审、评审中、待补充、已通过、已拒绝、已转任务、已归档）
- `RequirementPriority`: 优先级（低、中、高、紧急）
- `RequirementComplexity`: 复杂度（简单、中等、复杂、非常复杂）

**核心接口**:
```typescript
interface Requirement {
  id: number;
  display_id: string;
  title: string;
  description?: string;
  project_id?: number;
  enterprise_id: number;
  submitter_id: number;
  reviewer_id?: number;
  status: RequirementStatus | string;
  priority: RequirementPriority | string;
  // ... 其他字段
}

interface RequirementFilters {
  status?: string[];
  priority?: string[];
  category?: string[];
  submitter_id?: number;
  reviewer_id?: number;
  enterprise_id?: number;
  project_id?: number;
  search?: string;
  due_after?: string;
  due_before?: string;
  page?: number;
  page_size?: number;
  sort_by?: 'created_at' | 'updated_at' | 'due_date' | 'priority';
  sort_order?: 'asc' | 'desc';
}
```

**配置对象**:
- `REQUIREMENT_STATUS_CONFIG`: 状态显示配置（标签、颜色、图标）
- `REQUIREMENT_PRIORITY_CONFIG`: 优先级显示配置
- `REQUIREMENT_COMPLEXITY_CONFIG`: 复杂度显示配置

### 2. API服务层 (src/services/requirementService.ts)

扩展了现有的需求服务，新增完整的CRUD操作：

**核心方法**:
```typescript
class RequirementService {
  // 列表和详情
  async getRequirements(filters?: RequirementFilters): Promise<RequirementListResponse>
  async getRequirement(id: number): Promise<Requirement>
  
  // 创建和更新
  async createRequirement(request: CreateRequirementRequest): Promise<Requirement>
  async updateRequirement(id: number, request: UpdateRequirementRequest): Promise<Requirement>
  async deleteRequirement(id: number): Promise<void>
  
  // 流程操作
  async submitRequirement(id: number): Promise<Requirement>
  async reviewRequirement(id: number, request: ReviewRequirementRequest): Promise<Requirement>
  async convertToTask(id: number, request?: ConvertToTaskRequest): Promise<any>
  async archiveRequirement(id: number): Promise<Requirement>
  
  // 统计和批量操作
  async getStats(filters?: Pick<RequirementFilters, 'enterprise_id' | 'project_id'>): Promise<RequirementStats>
  async batchDeleteRequirements(ids: number[]): Promise<void>
  async batchUpdateStatus(ids: number[], status: string): Promise<void>
}
```

**特点**:
- 使用 `logApiError` 统一错误日志记录
- 数组参数自动转换为逗号分隔字符串
- 统计接口失败时返回默认值而不抛出错误
- 导出单例和便捷函数，支持多种导入方式

### 3. 需求列表页面 (src/pages/RequirementListPage.tsx)

实现了功能完整的需求列表页面：

**核心功能**:

1. **筛选功能**:
   - 关键词搜索（标题和描述）
   - 多选状态筛选
   - 多选优先级筛选
   - 日期范围筛选（截止日期）
   - 一键重置筛选

2. **表格功能**:
   - 分页展示
   - 每页数量调整
   - 显示总数和筛选结果统计
   - 列宽优化和固定列
   - 溢出文本省略显示

3. **操作功能**:
   - 查看需求详情
   - 编辑需求
   - 删除需求（带确认）
   - 提交评审（草稿状态）
   - 创建新需求

**表格列配置**:
```typescript
const columns = [
  '需求编号',      // display_id, 固定左侧
  '需求标题',      // 可点击跳转
  '状态',         // Tag显示，带图标和颜色
  '优先级',       // Tag显示，带图标和颜色
  '所属项目',     // 可能为空
  '提交人',
  '评审人',       // 可能为空
  '创建时间',     // 格式化显示
  '截止日期',     // 过期显示红色
  '操作'         // 固定右侧，条件显示按钮
];
```

**状态标签颜色映射**:
- 草稿: default灰色
- 待评审: blue蓝色
- 评审中: processing动态蓝色
- 待补充: warning橙色
- 已通过: success绿色
- 已拒绝: error红色
- 已转任务: purple紫色
- 已归档: default灰色

**优先级标签颜色映射**:
- 低: default灰色
- 中: blue蓝色
- 高: orange橙色
- 紧急: red红色

**交互优化**:
- 已转任务和已归档的需求禁止编辑
- 已转任务的需求禁止删除
- 仅草稿状态显示"提交评审"按钮
- 截止日期过期显示红色文字
- 列表加载状态显示Spin
- 操作失败显示友好错误信息
