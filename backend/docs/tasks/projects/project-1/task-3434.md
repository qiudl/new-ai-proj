# Task #3434: Phase 2.1 - 需求转任务功能实现文档

## 任务概述

实现需求管理系统的核心功能：将已批准的需求转换为可执行的任务。此功能允许用户将经过评审批准的需求直接转换为项目任务，保持需求和任务之间的关联关系。

## 技术架构

### 1. 数据库设计

#### requirement_tasks 关联表

该表在迁移 `20251105_01_requirement_mentions_and_task_linking.sql` 中创建：

```sql
CREATE TABLE IF NOT EXISTS requirement_tasks (
    id SERIAL PRIMARY KEY,
    requirement_id INTEGER NOT NULL REFERENCES requirements(id) ON DELETE CASCADE,
    task_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
    link_type VARCHAR(20) NOT NULL DEFAULT 'manual',
    linked_by INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    link_comment TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT unique_requirement_task_link UNIQUE (requirement_id, task_id),
    CONSTRAINT check_link_type CHECK (link_type IN ('manual', 'converted', 'related'))
);
```

**关键特性**:
- 支持多对多关系（一个需求可关联多个任务，一个任务可关联多个需求）
- 三种链接类型：`manual`(手动), `converted`(转换), `related`(相关)
- 唯一约束确保同一需求和任务不会重复关联

### 3. API实现

#### Handler方法 (handlers/requirement_handler.go:495-659)

**核心流程**:

1. **参数验证**
   - 验证需求ID有效性
   - 解析请求体

2. **权限检查**
   - 获取需求详情
   - 验证需求存在
   - 检查是否已转换（防止重复转换）
   - 验证需求状态为 "approved"

3. **任务数据准备**
   - 项目ID：使用请求中的或需求的项目ID
   - 任务标题：使用请求中的或默认为需求标题
   - 任务描述：自动生成Markdown格式描述
   - 优先级：使用请求中的或继承需求优先级
   - 截止日期：使用请求中的或继承需求截止日期

4. **任务描述自动生成**
```go
taskDescription := fmt.Sprintf("## 需求来源\n需求编号: %s\n\n", requirement.DisplayID)
if requirement.Description != nil {
    taskDescription += fmt.Sprintf("## 需求描述\n%s\n\n", *requirement.Description)
}
if requirement.AcceptanceCriteria != nil {
    taskDescription += fmt.Sprintf("## 验收标准\n%s\n\n", *requirement.AcceptanceCriteria)
}
if requirement.BusinessValue != nil {
    taskDescription += fmt.Sprintf("## 商业价值\n%s\n", *requirement.BusinessValue)
}
```

5. **创建任务**
   - 使用 `h.db.Tasks().Create()` 创建任务
   - 状态默认为 "todo"

6. **创建需求-任务关联**
   - 使用原生SQL插入 `requirement_tasks` 表
   - 链接类型设置为 "converted"
   - 可选的评论说明

7. **更新需求状态**
   - 使用 `h.db.Requirements().SetConvertedTask()` 方法
   - 设置 `converted_task_id`, `converted_at`, `converted_by`
   - 更新状态为 "converted"

## 业务规则

### 转换前提条件

1. **需求状态**: 必须是 "approved" 状态
2. **重复检查**: 未曾转换过（`converted_task_id` 为空）
3. **项目归属**: 必须指定有效的项目ID

### 转换流程

```
需求(approved) → 验证 → 创建任务 → 创建关联 → 更新需求状态(converted)
```

### 数据继承规则

| 字段 | 继承规则 |
|------|----------|
| 项目ID | 请求指定 > 需求项目ID |
| 任务标题 | 请求指定 > 需求标题 |
| 优先级 | 请求指定 > 需求优先级 > "medium" |
| 截止日期 | 请求指定 > 需求截止日期 |
| 任务描述 | 请求指定 > 自动生成(需求信息汇总) |

## 技术亮点

### 1. 智能描述生成

自动将需求的多个字段组合成结构化的任务描述：
- 需求来源和编号
- 详细描述
- 验收标准
- 商业价值

这确保了任务包含完整的背景信息，便于开发人员理解和执行。

### 2. 防重复机制

通过检查 `converted_task_id` 字段，防止同一需求被多次转换，确保数据一致性。

### 3. 灵活的参数控制

允许在转换时：
- 覆盖需求的默认值（项目、优先级、标题等）
- 可选添加关联评论
- 为未来的子任务创建预留接口

### 4. 事务安全

虽然当前实现中任务创建、关联创建、需求更新是独立操作，但都有错误处理和日志记录，即使某步失败也会继续后续操作并记录错误。

### 5. 错误处理策略

```go
// 关联创建失败时继续
if err != nil {
    log.Printf("Error creating requirement-task link: ...")
    // Continue even if link creation fails
}

// 状态更新失败时继续
if err != nil {
    log.Printf("Error updating requirement after conversion: ...")
    // Continue even if update fails - task is created
}
```

这种策略确保即使某些辅助操作失败，核心任务仍然被创建。
