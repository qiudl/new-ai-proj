# 需求管理系统 - UI线框图设计及交互逻辑

## 📐 设计概述

本文档详细描述需求管理系统的UI线框图设计和交互逻辑，包括需求列表、需求详情、评论系统、@用户功能等核心界面。

## 🎨 设计原则

1. **一致性**: 遵循Ant Design设计规范
2. **易用性**: 清晰的视觉层级，直观的操作流程
3. **响应式**: 适配桌面端和移动端
4. **高效性**: 减少用户操作步骤，提供快捷操作
5. **可访问性**: 支持键盘导航，符合WCAG标准

## 📱 页面架构

```
需求管理系统
├── 需求列表页 (RequirementList)
├── 需求创建/编辑页 (RequirementForm)
├── 需求详情页 (RequirementDetail)
└── 我的需求页 (MyRequirements)
```

### 交互逻辑

#### 1.1 搜索功能
- **触发**: 输入关键词后300ms防抖搜索
- **范围**: 搜索需求标题、描述、需求编号
- **反馈**: 显示搜索结果数量，高亮匹配关键词

#### 1.2 筛选器
- **展开/收起**: 默认收起，点击"高级筛选"展开
- **多选组合**: 支持多个条件组合筛选
- **实时过滤**: 选择条件后立即更新列表
- **清空筛选**: 一键清空所有筛选条件
- **筛选器保存**: 记住用户上次的筛选条件（LocalStorage）

#### 1.3 视图切换
- **列表视图**: 默认视图，显示详细信息
- **看板视图**: 按状态分组的卡片视图（Draft/Pending/Reviewing/Approved/Rejected）
- **统计视图**: 图表展示需求统计数据

#### 1.4 快速操作
- **快速评审**: 
  - 鼠标悬停显示"快速评审"按钮
  - 点击弹出快速评审对话框
  - 可选：通过/拒绝/需要补充
  - 输入简短评审意见
  
- **转为任务**:
  - 仅"已通过"状态显示
  - 点击打开转换对话框
  - 自动填充需求信息到任务表单
  
#### 1.5 排序
- 支持排序: 最新、最早、优先级、评论数
- 点击切换升序/降序

### 交互逻辑

#### 2.1 表单验证
- **实时验证**: 失焦时验证字段
- **必填提示**: 标题、描述为必填，标记*号
- **字数限制**: 标题500字符，实时显示剩余字数
- **格式验证**: 日期格式、优先级选择等

#### 2.2 自动保存
- **草稿保存**: 每30秒自动保存到LocalStorage
- **提示恢复**: 页面加载时检测草稿，提示"检测到未完成的需求，是否恢复？"
- **清空草稿**: 成功提交后清空草稿

#### 2.3 Markdown编辑器
- **实时预览**: 支持编辑/预览模式切换
- **工具栏**: 粗体、斜体、代码、链接、图片、表格等快捷按钮
- **快捷键**: Ctrl+B粗体、Ctrl+I斜体等
- **图片上传**: 拖拽或粘贴图片直接上传

#### 2.4 附件上传
- **拖拽上传**: 支持拖拽文件到上传区域
- **批量上传**: 可同时选择多个文件
- **进度显示**: 显示上传进度条
- **文件预览**: 图片可直接预览，PDF/Word显示图标
- **大小限制**: 单文件最大10MB，总计最大50MB

#### 2.5 提交流程
```
点击"提交评审" 
  ↓
表单验证
  ↓
确认对话框："确定提交评审？提交后将通知项目经理"
  ↓
提交中（显示Loading）
  ↓
成功: 
  - 显示成功消息："需求已提交，编号: REQ-2025-0001"
  - 3秒后跳转到需求详情页
失败:
  - 显示错误消息
  - 保持在当前页面
```

### 交互逻辑

#### 3.1 需求状态流转
```
草稿 → 待评审 → 评审中 → 已通过/已拒绝/待补充
                             ↓
                         转为任务/归档
```

**状态操作权限**:
- 草稿 → 待评审: 提交人
- 待评审 → 评审中: 评审人
- 评审中 → 已通过/已拒绝/待补充: 评审人
- 已通过 → 转为任务: 项目经理
- 任何状态 → 归档: 管理员

#### 3.2 @用户功能

**输入交互**:
1. 输入`@`触发用户选择器
2. 显示企业用户列表，支持搜索
3. 上下键选择，回车确认
4. 选中后显示`@用户名`蓝色高亮

**用户搜索**:
```
输入: @李
显示: 
┌──────────────────┐
│ 👤 李经理       │
│    项目经理     │
├──────────────────┤
│ 👤 李工程师     │
│    开发工程师   │
├──────────────────┤
│ 👤 李测试       │
│    测试工程师   │
└──────────────────┘
```

**通知发送**:
- 评论发布后，立即向被@用户发送通知
- 通知内容："{用户名} 在需求 {需求编号} 中@了你"
- 通知方式：站内信 + WebSocket实时推送 + 邮件（可配置）

#### 3.3 评论操作

**点赞**:
- 点击👍切换点赞状态
- 显示点赞数量
- 点赞用户列表气泡提示

**回复**:
- 点击"回复"按钮
- 评论框自动填充`@用户名`
- 回复显示在原评论下方，缩进显示

**置顶**:
- 仅项目经理/管理员可见
- 点击"置顶"将评论移到顶部
- 显示📌图标
- 最多置顶3条

**删除**:
- 评论作者可删除自己的评论
- 项目经理/管理员可删除任何评论
- 删除前确认："确定删除此评论？此操作不可恢复"
- 软删除，保留历史记录

#### 3.4 评论筛选
- **全部**: 显示所有评论
- **只看重要**: 仅显示置顶评论和评审意见
- **按类型**: 一般/提问/建议/批准
- **按时间**: 最新/最早

## 🔟 无障碍设计 (A11y)

### 键盘导航
- `Tab`: 切换焦点
- `Enter`: 确认操作
- `Esc`: 关闭对话框
- `Space`: 选择/取消选择
- `↑/↓`: 列表导航
- `Ctrl+Enter`: 快速提交评论

### 屏幕阅读器支持
```html

<article
  role="article"
  aria-labelledby="req-title-001"
  aria-describedby="req-desc-001"
>
  <h3 id="req-title-001">用户登录流程优化需求</h3>
  <p id="req-desc-001">当前用户登录流程存在以下问题...</p>

<div
  role="listbox"
  aria-label="选择要@的用户"
  aria-activedescendant="user-123"
>
  <div role="option" id="user-123">李经理</div>
</div>

  aria-label="输入评论内容"
  aria-describedby="comment-hint"

```

### 颜色对比度
- 文本与背景对比度 ≥ 4.5:1
- 大文本与背景对比度 ≥ 3:1
- 状态颜色区分（不仅依赖颜色）：
  - 待评审: 🟡 + "待评审"文字
  - 已通过: 🟢 + "已通过"文字
  - 已拒绝: 🔴 + "已拒绝"文字
