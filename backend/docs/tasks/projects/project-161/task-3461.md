# 品类管理模块产品需求文档 (PRD)

**项目**: Coolbuy 3.0 B2B电商平台  
**模块**: 品类管理 (Category Management)  
**版本**: v1.0  
**撰写日期**: 2025-01-06

---

## 1. 产品概述

### 1.1 功能简介
品类管理模块负责商品分类体系的创建、编辑、维护，支持树形层级结构管理，为商品组织提供清晰的分类导航，支持"李宁"、"百丽"、"波司登"等品牌的多级分类体系。

### 1.2 业务价值
- 建立清晰的商品分类体系，便于用户快速查找商品
- 支持多品牌、多公司的独立分类管理
- 支持分类图片展示，提升用户体验
- 为SPU、SKU提供分类归属，便于数据分析和统计

### 1.3 用户角色
- **商品管理员**: 创建、编辑、删除品类
- **运营人员**: 维护分类图片、排序
- **采购人员**: 按分类查看商品
- **销售人员**: 按分类查询商品信息

## 2. 核心功能需求

### 2.1 品类树形结构管理

#### 2.1.1 功能描述
支持无限层级的树形分类结构，典型场景为2-3级分类。

#### 2.1.2 数据字段
| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| categoryCode | String | 是 | 分类编码（唯一） | CAT_001 |
| categoryName | String | 是 | 分类名称 | 运动鞋 |
| parentId | String | 否 | 父分类ID（空为根分类） | null |
| treeLevel | Integer | 是 | 层级（1/2/3...） | 1 |
| isLeaf | Boolean | 是 | 是否叶子节点 | false |
| imgUrl | String | 否 | 分类图片URL | /images/cat_001.jpg |
| companyId | String | 是 | 公司ID（多租户隔离） | company_001 |
| status | Boolean | 是 | 启用状态 | true |
| sortNo | Integer | 否 | 排序号 | 1 |
| remark | String | 否 | 备注 | 热门分类 |

#### 2.1.3 业务规则
- 根分类（一级分类）的`parentId`为空或空字符串
- 创建子分类时，父分类的`isLeaf`自动设为`false`
- 删除分类时，如果父分类下没有其他子分类，父分类的`isLeaf`自动设为`true`
- 同一公司下，分类编码不能重复
- 最大支持5级分类（建议使用2-3级）

#### 2.1.4 树形结构示例
```
李宁品牌分类树
├─ 运动鞋 (一级)
│  ├─ 跑步鞋 (二级)
│  ├─ 篮球鞋 (二级)
│  └─ 休闲鞋 (二级)
├─ 运动服 (一级)
│  ├─ T恤 (二级)
│  ├─ 外套 (二级)
│  └─ 裤子 (二级)
└─ 运动配件 (一级)
   ├─ 帽子 (二级)
   └─ 袜子 (二级)
```

**业务逻辑**:
1. 验证分类编码唯一性
2. 如果选择了父分类，将父分类的`isLeaf`设为`false`
3. 自动计算`treeLevel`（父分类的level + 1）
4. 生成分类ID并保存

#### 2.2.2 编辑品类

**业务规则**:
- 可以修改分类名称、排序号、状态、备注、图片
- 不允许修改分类编码（防止数据混乱）
- 不允许将有子分类的分类设为叶子节点
- 修改父分类时，需要重新计算`treeLevel`

#### 2.2.3 删除品类

**业务规则**:
1. 检查是否有子分类，如果有则不允许删除
2. 检查是否有商品（SPU/SKU）关联，如果有则不允许删除
3. 删除后，检查父分类是否还有其他子分类，如果没有则将父分类的`isLeaf`设为`true`

### 2.6 品类排序与拖拽

#### 2.6.1 功能描述
支持通过拖拽调整分类的排序，影响前端展示顺序。

- 拖拽后自动更新`sort_no`字段
- 排序后实时生效

## 3. 非功能性需求

### 3.1 性能要求
| 指标 | 目标值 |
|------|--------|
| 分类树查询响应时间 | < 300ms (500个分类) |
| 分类详情查询响应时间 | < 100ms |
| 分类创建/更新响应时间 | < 200ms |
| 并发支持 | 50 QPS |

### 3.2 数据一致性
- 父子关系必须有效（父分类必须存在）
- 删除分类时检查子分类和商品关联
- 使用乐观锁机制（version字段）防止并发冲突
- 分类树的`isLeaf`字段自动维护

### 3.3 多租户隔离
- 每个公司（brand_supplier）有独立的分类树
- 不同公司的分类编码可以重复
- 查询时自动过滤当前公司的分类

### 3.4 数据迁移
- 从cool_belle的`prd_product_category`表迁移约200条分类数据
- 从cool_lining的`prd_product_category`表迁移约150条分类数据
- 迁移数据包括: 基本信息、层级关系、图片URL

## 4. 数据库设计

### 4.1 核心表结构

#### product_categories (品类表)
```sql
CREATE TABLE product_categories (
    id UUID PRIMARY KEY,
    category_code VARCHAR(50) NOT NULL,
    category_name VARCHAR(100) NOT NULL,
    parent_id UUID REFERENCES product_categories(id) ON DELETE RESTRICT,
    tree_level INTEGER NOT NULL DEFAULT 1,
    is_leaf BOOLEAN NOT NULL DEFAULT true,
    img_url VARCHAR(500),
    company_id UUID NOT NULL,
    status BOOLEAN DEFAULT true,
    is_delete BOOLEAN DEFAULT false,
    sort_no INTEGER DEFAULT 0,
    remark TEXT,
    version INTEGER DEFAULT 1,
    input_user_id UUID,
    input_user_name VARCHAR(50),
    input_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_user_id UUID,
    update_user_name VARCHAR(50),
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    INDEX idx_parent_id (parent_id),
    INDEX idx_company_id (company_id),
    INDEX idx_category_code (category_code),
    INDEX idx_tree_level (tree_level),
    INDEX idx_sort_no (sort_no),
    UNIQUE KEY uk_category_code_company (category_code, company_id)
);

COMMENT ON TABLE product_categories IS '商品分类表';
COMMENT ON COLUMN product_categories.category_code IS '分类编码（公司内唯一）';
COMMENT ON COLUMN product_categories.category_name IS '分类名称';
COMMENT ON COLUMN product_categories.parent_id IS '父分类ID（空为根分类）';
COMMENT ON COLUMN product_categories.tree_level IS '层级（1/2/3...）';
COMMENT ON COLUMN product_categories.is_leaf IS '是否叶子节点';
COMMENT ON COLUMN product_categories.img_url IS '分类图片URL';
```

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 分类树深度过大导致查询慢 | 中 | 限制最大层级为5级、使用异步加载 |
| 删除分类时未检查关联导致数据错误 | 高 | 删除前强制检查商品关联、子分类 |
| 多租户数据混乱 | 高 | 数据库唯一约束、API层强制过滤 |
| 图片上传占用大量存储空间 | 低 | 限制图片大小、使用CDN加速 |
