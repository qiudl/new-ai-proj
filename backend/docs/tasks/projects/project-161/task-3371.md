# 仓库库存数据库Schema设计文档

## 1. 概述

### 1.1 设计目标

本文档描述了Coolbuy 3.0仓库库存模块的完整数据库Schema设计，实现:

- ✅ **多仓库管理**: 支持多个仓库、库区、库位的层级管理
- ✅ **实时库存**: 精确的库存数量跟踪和预留机制
- ✅ **出入库管理**: 完整的入库、出库、调拨、盘点流程
- ✅ **库存事务**: 所有库存变动的详细记录和审计
- ✅ **多租户隔离**: PostgreSQL Schema隔离确保数据安全
- ✅ **库存预警**: 库存上下限预警和智能补货建议

### 1.2 核心概念

| 概念 | 说明 | 示例 |
|------|------|------|
| 仓库 (Warehouse) | 物理仓库，一级存储单元 | 北京仓、上海仓 |
| 库区 (Zone) | 仓库内的区域划分 | A区、B区 |
| 库位 (Location) | 具体的存储位置 | A01-01-01 |
| 库存 (Inventory) | SKU在特定位置的数量 | SKU-001在A01-01-01有100件 |
| 可用库存 | 实际库存 - 预留库存 | 100 - 20 = 80件可售 |
| 预留库存 | 已下单但未出库的数量 | 订单锁定20件 |

### 1.3 设计原则

1. **Schema隔离**: 使用PostgreSQL Schema实现租户数据隔离
2. **ACID事务**: 库存操作必须保证事务完整性
3. **软删除**: 核心表使用deleted_at实现软删除
4. **审计追踪**: 所有库存变动记录完整日志
5. **并发控制**: 使用乐观锁或悲观锁防止超卖
6. **索引优化**: 为高频查询字段建立合适索引

## 3. 库存核心表

### 3.1 库存表 (inventories)

**SKU在各仓库的库存数量**

| 字段名 | 类型 | 索引 | 约束 | 说明 |
|--------|------|------|------|------|
| id | BIGSERIAL | PK | NOT NULL | 主键 |
| warehouse_id | BIGINT | INDEX | NOT NULL, FK | 仓库ID |
| sku_id | BIGINT | INDEX | NOT NULL, FK | SKU ID |
| location_id | BIGINT | INDEX | FK | 库位ID |
| quantity | INT | INDEX | NOT NULL | 实际库存数量 |
| available_quantity | INT | - | NOT NULL | 可用库存 |
| reserved_quantity | INT | - | NOT NULL | 预留库存 |
| defective_quantity | INT | - | DEFAULT 0 | 残次品数量 |
| in_transit_quantity | INT | - | DEFAULT 0 | 在途数量 |
| batch_number | VARCHAR(100) | INDEX | - | 批次号 |
| production_date | DATE | - | - | 生产日期 |
| expiry_date | DATE | INDEX | - | 过期日期 |
| cost_price | DECIMAL(10,2) | - | - | 成本价 |
| last_inbound_at | TIMESTAMP | - | - | 最后入库时间 |
| last_outbound_at | TIMESTAMP | - | - | 最后出库时间 |
| version | INT | - | DEFAULT 1 | 版本号(乐观锁) |
| created_at | TIMESTAMP | - | - | 创建时间 |
| updated_at | TIMESTAMP | - | - | 更新时间 |
| deleted_at | TIMESTAMP | INDEX | - | 软删除时间 |

#### 关键计算

```go
// 可用库存 = 实际库存 - 预留库存 - 残次品
available_quantity = quantity - reserved_quantity - defective_quantity

// 库存检查
if available_quantity < order_quantity {
    return errors.New("库存不足")
}
```

#### 唯一约束

```sql
-- 同一仓库、同一SKU、同一库位、同一批次的库存唯一
CREATE UNIQUE INDEX idx_inventories_unique 
ON inventories(warehouse_id, sku_id, location_id, batch_number) 
WHERE deleted_at IS NULL;
```

#### 索引设计

```sql
CREATE INDEX idx_inventories_warehouse_sku ON inventories(warehouse_id, sku_id);
CREATE INDEX idx_inventories_quantity ON inventories(quantity) WHERE quantity > 0;
CREATE INDEX idx_inventories_available ON inventories(available_quantity) WHERE available_quantity > 0;
CREATE INDEX idx_inventories_batch ON inventories(batch_number);
CREATE INDEX idx_inventories_expiry ON inventories(expiry_date);
```

## 10. 关键业务流程

### 10.1 采购入库流程

```sql
BEGIN TRANSACTION;

-- 1. 创建入库单
INSERT INTO inbound_orders (...) VALUES (...);

-- 2. 添加入库明细
INSERT INTO inbound_items (...) VALUES (...);

-- 3. 更新库存
INSERT INTO inventories (warehouse_id, sku_id, quantity, ...)
VALUES (...)
ON CONFLICT (warehouse_id, sku_id, location_id, batch_number)
DO UPDATE SET 
    quantity = inventories.quantity + EXCLUDED.quantity,
    available_quantity = inventories.available_quantity + EXCLUDED.quantity;

-- 4. 记录库存流水
INSERT INTO inventory_transactions (...) VALUES (...);

-- 5. 更新入库单状态
UPDATE inbound_orders SET status = 'completed' WHERE id = ?;

COMMIT;
```

---

### 10.2 销售出库流程

```sql
BEGIN TRANSACTION;

-- 1. 检查可用库存
SELECT available_quantity 
FROM inventories 
WHERE warehouse_id = ? AND sku_id = ?
FOR UPDATE;  -- 悲观锁

-- 2. 创建库存预留
INSERT INTO inventory_reservations (...) VALUES (...);

-- 3. 更新库存预留数量
UPDATE inventories 
SET reserved_quantity = reserved_quantity + ?
WHERE id = ?;

-- 4. 创建出库单
INSERT INTO outbound_orders (...) VALUES (...);

-- 5. 添加出库明细
INSERT INTO outbound_items (...) VALUES (...);

COMMIT;

-- --- 拣货完成后 ---

BEGIN TRANSACTION;

-- 6. 扣减实际库存
UPDATE inventories 
SET quantity = quantity - ?,
    reserved_quantity = reserved_quantity - ?,
    available_quantity = available_quantity
WHERE id = ?;

-- 7. 更新预留记录
UPDATE inventory_reservations 
SET status = 'fulfilled', fulfilled_at = NOW()
WHERE id = ?;

-- 8. 记录库存流水
INSERT INTO inventory_transactions (...) VALUES (...);

-- 9. 更新出库单状态
UPDATE outbound_orders SET status = 'shipped' WHERE id = ?;

COMMIT;
```

## 11. 并发控制策略

### 11.1 乐观锁 (Optimistic Locking)

```go
// 使用版本号控制
type Inventory struct {
    ID       uint
    Quantity int
    Version  int  // 版本号
}

// 更新时检查版本
func UpdateInventory(db *gorm.DB, inv *Inventory, changeQty int) error {
    result := db.Model(&Inventory{}).
        Where("id = ? AND version = ?", inv.ID, inv.Version).
        Updates(map[string]interface{}{
            "quantity": gorm.Expr("quantity + ?", changeQty),
            "version": gorm.Expr("version + 1"),
        })
    
    if result.RowsAffected == 0 {
        return errors.New("库存已被其他操作修改，请重试")
    }
    
    return nil
}
```

### 11.2 悲观锁 (Pessimistic Locking)

```go
// 查询时加锁
func GetInventoryForUpdate(db *gorm.DB, warehouseID, skuID uint) (*Inventory, error) {
    var inv Inventory
    err := db.Set("gorm:query_option", "FOR UPDATE").
        Where("warehouse_id = ? AND sku_id = ?", warehouseID, skuID).
        First(&inv).Error
    
    return &inv, err
}
```

### 11.3 分布式锁 (使用Redis)

```go
// Redis分布式锁
func AcquireInventoryLock(redis *redis.Client, skuID uint) (bool, error) {
    lockKey := fmt.Sprintf("inventory:lock:%d", skuID)
    
    // 尝试获取锁，30秒超时
    result, err := redis.SetNX(context.Background(), lockKey, 1, 30*time.Second).Result()
    return result, err
}

func ReleaseInventoryLock(redis *redis.Client, skuID uint) error {
    lockKey := fmt.Sprintf("inventory:lock:%d", skuID)
    return redis.Del(context.Background(), lockKey).Err()
}
```

## 14. 性能优化

### 14.1 查询优化

```sql
-- 好: 使用索引
SELECT * FROM inventories 
WHERE warehouse_id = 1 AND sku_id = 100;

-- 差: 全表扫描
SELECT * FROM inventories 
WHERE quantity > 0 OR available_quantity > 0;

SELECT * FROM inventories WHERE quantity > 0
```
