## 测试最佳实践

### 1. 测试结构

```go
func TestXxx(t *testing.T) {
    // Setup
    db := setupTestDB(t)
    
    // Test cases
    tests := []struct {
        name    string
        input   interface{}
        wantErr bool
    }{
        {
            name: "Success case",
            input: validInput,
            wantErr: false,
        },
        {
            name: "Error case",
            input: invalidInput,
            wantErr: true,
        },
    }
    
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // Test logic
            result, err := functionUnderTest(tt.input)
            
            // Assertions
            if tt.wantErr {
                assert.Error(t, err)
            } else {
                assert.NoError(t, err)
                assert.Equal(t, expected, result)
            }
        })
    }
}
```

### 2. 测试数据隔离

- 每个测试使用独立的数据库实例
- 使用 `t.Cleanup()` 清理测试资源
- 避免测试之间的依赖

### 3. Mock 外部依赖

- 数据库: 使用 SQLite 内存数据库
- HTTP 请求: 使用 httptest
- 外部服务: 使用 mock 对象

### 4. 测试覆盖率目标

- **Store 层**: ≥ 90%
- **Biz 层**: ≥ 80%
- **Ctrl 层**: ≥ 70%

## Store 层测试示例

以下是一个完整的 Store 层测试示例：

```go
func TestSysUserStore_GetByUsername(t *testing.T) {
    db := setupTestDB(t)
    store := newTestSysUserStore(db)

    // Create test user
    testUser := createTestUser(t, db, "testuser")

    tests := []struct {
        name     string
        username string
        wantErr  bool
    }{
        {
            name:     "Existing user",
            username: "testuser",
            wantErr:  false,
        },
        {
            name:     "Non-existent user",
            username: "nonexistent",
            wantErr:  true,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            ctx := context.Background()
            user, err := store.GetByUsername(ctx, tt.username)

            if tt.wantErr {
                assert.Error(t, err)
                assert.Nil(t, user)
            } else {
                assert.NoError(t, err)
                assert.NotNil(t, user)
                assert.Equal(t, testUser.Username, user.Username)
            }
        })
    }
}
```

## 测试辅助函数

```go
func setupTestDB(t *testing.T) *gorm.DB {
    db, err := gorm.Open(sqlite.Open(":memory:"), &gorm.Config{})
    require.NoError(t, err, "Failed to open test database")

    // Auto-migrate
    err = db.AutoMigrate(&model.SysUserModel{})
    require.NoError(t, err, "Failed to migrate test schema")

    return db
}
```

## 已知问题和限制

1. **Biz 层测试复杂度**
   - 业务层依赖较多外部服务（SMS、邮件等）
   - 需要更多的 mock 处理
   - 上下文管理较复杂

2. **集成测试环境**
   - 需要完整的数据库环境
   - 需要处理事务和并发问题
   - 测试数据隔离较困难

3. **性能测试**
   - 基准测试数据量有限
   - 缺少压力测试
   - 缺少并发测试
