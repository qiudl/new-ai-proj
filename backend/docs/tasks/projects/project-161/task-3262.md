## 业务流程

### 1. 完整报价流程

```
[创建] → [编辑] → [发送] → [客户查看] → [客户响应] → [转订单]
draft    draft     sent      viewed       accepted      converted
                                          rejected
                                          expired
```

### 2. 状态转换规则

| 当前状态 | 可执行操作 | 转换后状态 |
|---------|----------|-----------|
| `draft` | 编辑/删除/发送 | `sent` |
| `pending` | 编辑/发送 | `sent` |
| `sent` | 响应 | `accepted` / `rejected` |
| `viewed` | 响应 | `accepted` / `rejected` |
| `accepted` | 转订单 | `converted` |
| `expired` | 无 | - |
| `converted` | 无 | - |

### 3. 权限控制

- **可编辑**: 仅`draft`和`pending`状态
- **可删除**: 仅`draft`状态
- **可发送**: `draft`和`pending`状态
- **可响应**: `sent`和`viewed`状态
- **可转订单**: `accepted`状态且未转换

## 关键设计决策

### 1. 报价单号生成策略
- **格式**: `CQ{TenantID}-YYYYMMDD-XXX`
- **组成**:
  - `CQ` - Customer Quote缩写
  - `{TenantID}` - 租户隔离
  - `YYYYMMDD` - 日期便于追溯
  - `XXX` - 序列号（当前使用时间戳模1000，实际应用应使用数据库序列）

### 2. 金额计算
- **明细总额**: `(单价 × 数量) - 折扣金额`
- **折扣率优先**: 如果设置了`discount_rate`，自动计算`discount_amount`
- **自动计算**: 通过GORM钩子在保存前自动计算，确保数据一致性

### 3. 软删除
- 使用GORM的`DeletedAt`字段
- 已删除记录不在常规查询中显示
- 保留历史数据用于审计

### 4. 多租户隔离
- 所有表包含`tenant_id`字段
- 查询自动添加租户过滤条件（通过中间件）
- 租户间数据完全隔离

### 5. 事务一致性
- Create/Update/Delete操作使用事务
- 确保主表和明细表数据的原子性
- 失败自动回滚
