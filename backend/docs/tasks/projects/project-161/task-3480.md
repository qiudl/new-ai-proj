# 资金流水模块API设计文档（Swagger/OpenAPI 3.0）

## 文档概述

本文档提供资金流水模块的完整API规范，采用OpenAPI 3.0标准，涵盖账户管理、交易记录、支付收款、退款、提现、结算等核心功能的所有HTTP接口。

## OpenAPI 3.0 规范

### 基础配置

info:
  title: 资金流水模块 API
  description: |
    Coolbuy 3.0 资金流水管理系统API文档
    
    ## 核心功能
    - 账户管理：客户、供应商、公司、员工账户的创建、查询、余额管理
    - 交易记录：完整的资金流水记录、查询、统计、导出
    - 支付收款：订单支付（余额/支付宝/微信/银行转账）、充值、回调处理
    - 退款管理：退款申请、审批、处理、查询
    - 提现管理：提现申请、审批、处理、银行卡管理
    - 结算管理：客户/供应商结算、审批流程、结算统计
    
    ## 多租户架构
    本系统采用PostgreSQL Schema隔离实现多租户，所有API请求需携带 `X-Tenant-ID` 头部。
    
    ## 认证方式
    使用JWT Bearer Token认证，在所有请求的 `Authorization` 头部携带Token。

## API设计原则与最佳实践

### 1. RESTful设计原则

- **资源导向**: 所有端点围绕资源设计（accounts、transactions、payments等）
- **HTTP方法语义化**: 
  - GET: 查询操作
  - POST: 创建资源、执行操作
  - PUT: 更新资源
  - DELETE: 删除资源
- **统一的URL结构**: `/api/v1/{resource}/{id}/{action}`

### 2. 多租户隔离

- 所有API请求必须携带 `X-Tenant-ID` 头部
- 后端通过PostgreSQL Schema进行数据隔离
- 中间件自动验证租户ID并切换数据库上下文

### 3. 认证与授权

**JWT认证**:
```yaml
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Token包含信息**:
- user_id: 用户ID
- username: 用户名
- role: 用户角色
- tenant_id: 租户ID
- exp: 过期时间

### 4. 统一的响应格式

**成功响应**:
```json
{
  "data": {
    // 业务数据
  }
}
```

**错误响应**:
```json
{
  "error": "错误描述信息"
}
```

**分页响应**:
```json
{
  "data": {
    "list": [],
    "pagination": {
      "total": 100,
      "page": 1,
      "page_size": 20,
      "total_pages": 5
    }
  }
}
```

### 5. 幂等性保证

**支付回调幂等性**:
- 基于 `payment_order_no` + `third_party_transaction_no` 唯一性
- 状态机防止重复处理
- 数据库唯一约束

**交易冲正幂等性**:
- 检查 `parent_transaction_no` 是否已存在冲正记录
- 防止同一交易被多次冲正

### 6. 金额处理规范

- 所有金额使用字符串格式传输，避免浮点数精度问题
- 正则验证: `^\d+(\.\d{1,2})?$`
- 后端使用 `shopspring/decimal` 库进行高精度计算
- 数据库使用 `DECIMAL(18,2)` 类型存储

### 7. 安全性设计

**输入验证**:
- 所有请求参数进行严格验证
- 金额范围检查
- 字符串长度限制
- 枚举值校验

**SQL注入防护**:
- 使用GORM参数化查询
- 禁止拼接SQL

**权限控制**:
- 基于角色的访问控制（RBAC）
- 数据权限隔离（租户级别）

### 8. 性能优化

**分页查询**:
- 默认分页大小: 20
- 最大分页大小: 100
- 大数据量使用游标分页

**索引优化**:
- 多维度查询字段建立复合索引
- 时间范围查询优化

**缓存策略**:
- 账户信息缓存（Redis，TTL: 5分钟）
- 交易统计缓存（Redis，TTL: 10分钟）

### 9. API版本管理

- 通过URL路径管理版本: `/api/v1/`
- 保持向后兼容性
- 新版本不破坏旧版本客户端

|----------|---------|------|
