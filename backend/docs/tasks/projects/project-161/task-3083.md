# Category模块分层代码迁移方案

## 任务概述
将coolbuy3.0-backend的PMS分类模块迁移到paas-system/business-service的Product域，适配新的Schema隔离多租户架构。

## 架构差异分析

### 旧系统架构（coolbuy3.0-backend）
```
多租户策略: 基于tenant_id字段
数据库访问: core.Store[T].TenantDB(c) - 自动添加WHERE tenant_id过滤
模型基类: core.Model (包含ID, TenantID, CreatedAt等)
表名: pms_spu_category
上下文: gin.Context贯穿所有层
```

### 新系统架构（paas-system/business-service）
```
多租户策略: 基于PostgreSQL Schema隔离
数据库访问: middleware.GetTenantDB(c) - 返回已切换schema的DB
模型: 独立定义，无TenantID字段
表名: categories (简化命名)
上下文: gin.Context仅在Handler/Ctrl层，Biz/Store层使用*gorm.DB
```

## 关键变更

### 1. 多租户隔离方式变更
**旧**: 所有租户数据在同一schema，通过tenant_id字段区分
```go
// 旧系统：自动添加 WHERE tenant_id = ?
s.TenantDB(c).Find(&categories)
```

**新**: 每个租户独立schema，通过切换search_path隔离
```go
// 新系统：已在租户schema中，无需tenant_id
db, _ := middleware.GetTenantDB(c)
db.Find(&categories)
```

### 2. Model层差异

**旧模型** (spu_category_model.go):
```go
type Category struct {
    core.Model  // 包含TenantID
    CategoryName string
    CategoryCode string
    Level        int
    Pid          int64
    Status       int
}
TableName: "pms_spu_category"
```

**新模型** (已存在于product/model/product.go):
```go
type Category struct {
    ID        uint           // 无TenantID字段
    Name      string         // 简化字段名
    ParentID  *uint          // 使用指针支持NULL
    Sort      int
    Status    string         // 改为string类型
    CreatedAt time.Time
    UpdatedAt time.Time
    DeletedAt gorm.DeletedAt
}
TableName: "categories"
```

### 3. 字段映射关系

| 旧字段 | 新字段 | 说明 |
|--------|--------|------|
| CategoryName | Name | 简化命名 |
| CategoryCode | (删除) | 新系统不使用编码 |
| Pid | ParentID | 使用*uint支持NULL |
| Status (int) | Status (string) | 类型变更 |
| Level | (自动计算) | 不存储，通过递归计算 |

## 迁移策略

### 1. Model层
**决策**: 使用已存在的新模型，不迁移旧模型
- 新模型已在`product/model/product.go`中定义
- 无需创建新文件
- 删除BeforeSave钩子（Level自动计算逻辑）

### 2. API层
**文件**: `api/category.go`
**迁移内容**:
- ReqListCategory - 列表请求
- RespListCategory - 列表响应
- Category - 数据传输对象
- ReqCreateCategory - 创建请求
- ReqUpdateCategory - 更新请求

**变更**:
- 删除CategoryCode相关字段
- 删除Level字段（自动计算）
- 使用paas-common的分页组件

### 3. Store层
**文件**: `store/category.go`
**迁移内容**:
- List() - 分页列表
- GetByID() - 根据ID查询
- GetByName() - 根据名称查询
- HasChildren() - 检查是否有子分类
- Create() - 创建
- Update() - 更新
- Delete() - 删除

**关键变更**:
```go
// 旧：继承core.Store，使用TenantDB(c)
type Category struct {
    core.Store[model.Category]
}
func (s *Category) List(c context.Context, r *api.ReqListCategory) {
    s.TenantDB(c).Find(...)  // 自动添加tenant_id过滤
}

// 新：独立结构体，接收DB参数
type CategoryStore struct {}
func (s *CategoryStore) List(db *gorm.DB, r *api.ReqListCategory) {
    db.Find(...)  // DB已在租户schema中
}
```

### 4. Biz层
**文件**: `biz/category.go`
**迁移内容**:
- List() - 列表业务逻辑
- Get() - 详情业务逻辑
- Create() - 创建业务逻辑
- Update() - 更新业务逻辑
- Delete() - 删除业务逻辑（含子分类检查）

**关键变更**:
```go
// 旧：使用gin.Context，Store自动处理租户
type Category struct {
    category store.Category
}
func (b *Category) List(c *gin.Context, r *v1.ReqListCategory) {
    b.category.List(c, r)  // 传递context
}

// 新：接收DB参数，显式传递
type CategoryBiz struct {
    store *store.CategoryStore
}
func (b *CategoryBiz) List(db *gorm.DB, r *api.ReqListCategory) {
    b.store.List(db, r)  // 显式传递DB
}
```

### 5. Ctrl层
**文件**: `ctrl/category.go`
**迁移内容**:
- List() - 列表控制器
- Get() - 详情控制器
- Create() - 创建控制器
- Update() - 更新控制器
- Delete() - 删除控制器

**关键变更**:
```go
// 旧：直接调用Biz层
func (ctrl *Category) List(c *gin.Context) {
    r := core.BindQuery[api.ReqListCategory](c)
    resp, err := ctrl.b.List(c, r)
    core.Write(c, resp, err)
}

// 新：先获取TenantDB，再调用Biz层
func (ctrl *CategoryCtrl) List(c *gin.Context) {
    db, err := middleware.GetTenantDB(c)
    if err != nil {
        c.JSON(500, gin.H{"error": "Tenant context not found"})
        return
    }
    var req api.ReqListCategory
    if err := c.ShouldBindQuery(&req); err != nil {
        c.JSON(400, gin.H{"error": err.Error()})
        return
    }
    resp, err := ctrl.biz.List(db, &req)
    if err != nil {
        c.JSON(500, gin.H{"error": err.Error()})
        return
    }
    c.JSON(200, resp)
}
```

## 实施步骤

### Step 1: 迁移API层 (15分钟)
1. 创建`api/category.go`
2. 定义请求/响应结构体
3. 移除CategoryCode、Level字段
4. 调整字段类型（Status: int→string）

### Step 2: 迁移Store层 (20分钟)
1. 创建`store/category.go`
2. 定义CategoryStore结构体
3. 实现CRUD方法，接收*gorm.DB参数
4. 移除TenantDB调用，直接使用传入的DB
5. 适配新模型字段（CategoryName→Name等）

### Step 3: 迁移Biz层 (20分钟)
1. 创建`biz/category.go`
2. 定义CategoryBiz结构体
3. 注入CategoryStore依赖
4. 实现业务逻辑，接收*gorm.DB参数
5. 保留HasChildren检查逻辑
6. 使用copier进行模型转换

### Step 4: 迁移Ctrl层 (15分钟)
1. 创建`ctrl/category.go`
2. 定义CategoryCtrl结构体
3. 注入CategoryBiz依赖
4. 在每个方法中先获取TenantDB
5. 处理参数绑定和响应
6. 保留Swagger注释

### Step 5: 更新Import路径 (10分钟)
1. 更新所有import为新的模块路径
2. 验证依赖关系
3. 确保编译通过

## 风险与注意事项

### 1. 字段映射风险
- CategoryCode字段删除：确认新系统不需要编码功能
- Level字段删除：需在查询时动态计算层级
- Status类型变更：需要映射 0/1 → "active"/"inactive"

### 2. 业务逻辑差异
- BeforeSave钩子删除：Level计算和CategoryCode验证逻辑需重新评估
- 唯一性约束：CategoryCode的唯一性验证需要替代方案

### 3. 测试建议
- 重点测试HasChildren逻辑
- 验证Schema隔离是否正确工作
- 测试分页查询
- 测试父子关系的级联操作
