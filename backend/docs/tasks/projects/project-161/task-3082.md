## 目录结构设计

### 方案选择
根据任务要求"Category模块迁移（6个文件）"和后续任务"迁移Category Model/Store/Biz/API/Ctrl层"，需要在product模块下创建完整的分层目录结构。

### 目标结构
```
business-service/internal/product/
├── api/          # 新建 - API定义层
│   └── .gitkeep
├── biz/          # 新建 - 业务逻辑层  
│   └── .gitkeep
├── ctrl/         # 新建 - 控制器层
│   └── .gitkeep
├── handler/      # 已存在
│   ├── category.go
│   └── product.go
├── model/        # 已存在
│   └── product.go
└── store/        # 新建 - 数据访问层
    └── .gitkeep
```

### 分层职责说明

1. **API层** (`api/`)
   - 定义HTTP请求和响应结构
   - 包含数据验证规则
   - 与外部接口解耦

2. **Store层** (`store/`)
   - 数据库CRUD操作
   - 继承`utils.Store[ModelType]`基类
   - 实现复杂查询逻辑

3. **Biz层** (`biz/`)
   - 核心业务逻辑处理
   - 调用Store层获取/存储数据
   - 实现业务规则和验证

4. **Ctrl层** (`ctrl/`)
   - 接收HTTP请求参数
   - 调用Biz层处理业务
   - 返回HTTP响应

5. **Handler层** (`handler/`)
   - 路由注册和中间件
   - 简单的请求转发
   - 调用Ctrl层

6. **Model层** (`model/`)
   - 数据库表结构定义
   - GORM模型和关联关系

## 实施步骤

### 1. 创建目录结构
```bash
cd paas-system/business-service/internal/product/
mkdir -p api biz ctrl store
```

### 2. 创建.gitkeep文件
为每个新目录创建.gitkeep文件，确保空目录被Git跟踪：
```bash
touch api/.gitkeep
touch biz/.gitkeep  
touch ctrl/.gitkeep
touch store/.gitkeep
```

### 3. 验证目录结构
```bash
tree paas-system/business-service/internal/product/
# 或
find paas-system/business-service/internal/product/ -type d | sort
```
