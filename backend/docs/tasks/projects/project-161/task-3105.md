### 架构特点

#### 1. 简化的分层架构

与原有的6层架构不同，新架构采用简化的Handler模式：

- **Model层**: 数据模型 + GORM Hooks（业务规则）
- **API层**: 请求/响应DTO定义
- **Handler层**: HTTP处理 + 业务逻辑
- **Router层**: 路由配置

**不再需要**:
- Store层（Handler直接使用GORM）
- Biz层（业务逻辑在Handler中）
- Ctrl层（由Handler替代）

#### 2. 多租户架构

**Schema级别隔离**:
```go
// 从context获取已切换到租户schema的DB
db, err := middleware.GetTenantDB(c)

// 直接查询，无需tenant_id字段
db.Find(&channels)  // 自动只返回当前租户数据
```

**优势**:
- Model无需tenant_id字段
- 查询逻辑更简洁
- 物理级别数据隔离

#### 3. GORM Hooks实现业务规则

```go
func (c *Channel) BeforeSave(tx *gorm.DB) error {
    // 1. 自动生成编码
    if c.Code == "" {
        c.Code = c.generateCode(tx)  // CH001, CH002...
    }
    
    // 2. 验证编码格式 (CHxxx or CH-xxx)
    if !c.isValidCode(c.Code) {
        return fmt.Errorf("invalid channel code format")
    }
    
    // 3. 检查名称重复
    if err := c.checkNameDuplicate(tx); err != nil {
        return err
    }
    
    // 4. 检查编码重复
    if err := c.checkCodeDuplicate(tx); err != nil {
        return err
    }
    
    // 5. 验证折扣率范围 (0.00-1.00)
    if c.Discount < 0 || c.Discount > 1 {
        return fmt.Errorf("discount must be between 0 and 1")
    }
    
    return nil
}
```

## 实现细节

### 1. Model层 (channel.go - 155行)

**数据结构**:
```go
type Channel struct {
    ID           uint           `gorm:"primaryKey;autoIncrement"`
    Code         string         `gorm:"type:varchar(100);uniqueIndex"`  // 渠道编码
    Name         string         `gorm:"type:varchar(200);not null"`     // 渠道名称
    Status       int            `gorm:"type:int;not null;default:1"`    // 状态
    Discount     float64        `gorm:"type:decimal(5,2);default:1.00"` // 折扣率
    ManagerID    uint           `gorm:"type:int"`                       // 负责人ID
    ManagerName  string         `gorm:"type:varchar(100)"`              // 负责人姓名
    SortNumber   uint           `gorm:"type:int;not null;default:0"`    // 排序号
    Description  string         `gorm:"type:text"`                      // 描述
    CreatedAt    time.Time
    UpdatedAt    time.Time
    DeletedAt    gorm.DeletedAt `gorm:"index"`
}
```

**核心功能**:

1. **自动编码生成** (`generateCode`):
   - 查询最大编码: `SELECT code FROM pms_channel WHERE code LIKE 'CH%' ORDER BY code DESC LIMIT 1`
   - 提取数字: 使用正则表达式 `\d+`
   - 递增生成: `CH001` → `CH002` → `CH003`

2. **编码格式验证** (`isValidCode`):
   - 正则表达式: `^CH-?\d{3,}$`
   - 支持格式: `CH001`, `CH-001`, `CH1234`

3. **唯一性检查**:
   - 名称重复检查 (`checkNameDuplicate`)
   - 编码重复检查 (`checkCodeDuplicate`)
   - 更新时排除当前ID: `WHERE id != ?`

4. **业务方法**:
   - `IsEnabled()`: 判断是否启用
   - `GetDiscountPercentage()`: 获取折扣百分比 (0.85 → 85%)
   - `CalculateDiscountedPrice()`: 计算折扣后价格

### 3. Handler层 (channel.go - 356行)

#### List - 列表查询
```go
func (h *ChannelHandler) List(c *gin.Context) {
    db, _ := middleware.GetTenantDB(c)
    
    // 绑定查询参数
    var req api.ReqListChannel
    c.ShouldBindQuery(&req)
    
    // 构建查询（支持模糊查询）
    query := db.Model(&model.Channel{})
    if req.Code != "" {
        query = query.Where("code LIKE ?", "%"+req.Code+"%")
    }
    if req.Name != "" {
        query = query.Where("name LIKE ?", "%"+req.Name+"%")
    }
    
    // 分页查询
    var total int64
    query.Count(&total)
    
    var channels []model.Channel
    offset := (req.Page - 1) * req.Limit
    query.Order("sort_number ASC, id DESC").
        Offset(offset).
        Limit(req.Limit).
        Find(&channels)
    
    // 转换为DTO并返回
    c.JSON(200, api.RespListChannel{Total: total, Data: data})
}
```

### 4. Router层 (router.go - 25行)

**路由配置**:
```go
func InitRouter(r *gin.RouterGroup, db *gorm.DB) {
    channelHandler := handler.NewChannelHandler(db)
    
    channel := r.Group("/channel")
    {
        channel.GET("", channelHandler.List)           // 列表
        channel.POST("", channelHandler.Create)        // 创建
        channel.GET("/comp", channelHandler.Comp)      // 组件（注意顺序）
        channel.GET("/:id", channelHandler.Get)        // 详情
        channel.PUT("/:id", channelHandler.Update)     // 更新
        channel.DELETE("/:id", channelHandler.Delete)  // 删除
    }
}
```

**路由顺序说明**:
- `/comp` 必须放在 `/:id` 之前
- 否则 `/comp` 会被 `/:id` 匹配，导致 `comp` 被当作ID

## 与原有实现的差异

### 1. 架构简化

**原有实现** (coolbuy3.0-backend):
```
Controller → Biz → Store → Model
   ↓          ↓      ↓       ↓
  HTTP     业务逻辑  DB操作  数据结构
```

**新实现** (paas-business):
```
Handler → Model (with Hooks)
   ↓         ↓
  HTTP    DB操作 + 业务规则
```

**优势**:
- 减少代码层数，降低复杂度
- 业务规则集中在Model层
- 维护成本更低

### 2. 多租户实现

**原有实现**:
```go
// Store层需要手动添加tenant_id过滤
query := db.Where("tenant_id = ?", tenantID)
```

**新实现**:
