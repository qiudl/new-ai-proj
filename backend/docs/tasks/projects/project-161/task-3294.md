## 三、Swagger生成问题分析

### 3.1 错误信息

```
ParseComment error in file .../channel_spu.go for comment: 
'@Param body body api.ReqUpdateStatus true "请求参数"': 
cannot find type definition: api.ReqUpdateStatus
```

### 3.2 问题分析

**问题类型**: 类型定义缺失

**原因**:
1. `api.ReqUpdateStatus` 类型未在对应的api包中定义
2. 或者该类型在其他包中，但swag无法解析
3. 可能是内部包导入问题

**影响范围**: 
- Channel模块的channel_spu接口
- 阻止整个Swagger文档生成

### 3.3 解决方案

#### 方案1: 修复类型定义（推荐）
```go
// 在 internal/channel/channel_spu/api/request.go 中添加
type ReqUpdateStatus struct {
    Status  string `json:"status" binding:"required"`
    Enabled bool   `json:"enabled"`
}
```

#### 方案2: 使用通用类型
```go
// 修改注释为
// @Param body body map[string]interface{} true "请求参数"
```

#### 方案3: 排除问题模块
```bash
# 仅为完成的模块生成文档
~/go/bin/swag init -g cmd/main.go -o docs/swagger \
    --exclude internal/channel
```

## 九、最佳实践建议

### 9.1 Swagger注释规范

**必须包含的字段**:
```go
// @Summary      简短描述（必须）
// @Description  详细描述（建议）
// @Tags         分类标签（必须）
// @Accept       json（必须）
// @Produce      json（必须）
// @Param        参数（根据需要）
// @Success      200 {object} ResponseType（必须）
// @Failure      400 {object} ErrorType（建议）
// @Router       /path [method]（必须）
// @Security     BearerAuth（需认证时必须）
```

### 9.2 类型定义规范

**API类型命名**:
- 请求: `ReqXxx` (如 `ReqCreateOrder`)
- 响应: `RespXxx` (如 `RespOrder`)
- 列表响应: `RespListXxx` (如 `RespListOrder`)

**导出规则**:
- 所有用于Swagger的类型必须导出（首字母大写）
- 字段必须有JSON标签
- 建议添加binding验证标签

### 9.3 文档维护流程

1. **添加新接口时**:
   - 同步添加Swagger注释
   - 更新Markdown文档

2. **修改接口时**:
   - 更新Swagger注释
   - 更新Markdown文档
   - 重新生成OpenAPI文档

3. **发布版本时**:
   - 验证所有文档完整性
   - 生成最新的OpenAPI文档
   - 更新API版本号
