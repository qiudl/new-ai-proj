# 任务 #3103: 迁移Express Store/Biz/API/Handler层

## 1. 任务概述

本任务是Express模块迁移的第三步，负责实现Express模块的API层（DTO定义）和Handler层（HTTP处理器），完成完整的HTTP API功能。

**注意**: 新架构采用简化的两层模式（API + Handler），不再使用旧架构的四层模式（API + Store + Biz + Ctrl）。

## 2. 架构对比

### 2.1 旧架构（四层模式）

```
Ctrl层 (express_controller.go)
  ↓ 调用
Biz层 (express_biz.go)
  ↓ 调用
Store层 (express_store.go)
  ↓ 使用
Model层 (express_model.go)
```

**特点**:
- 分层清晰，职责明确
- 代码冗余，简单CRUD也需要四层
- 依赖注入复杂

### 2.2 新架构（两层模式）

```
Handler层 (express.go)
  ↓ 直接使用
Model层 (express.go)
```

**特点**:
- 更简洁，减少样板代码
- Handler直接操作数据库
- 从context获取租户DB
- 适合简单CRUD场景

### 3.2 Handler层（HTTP处理器）

**文件**: `internal/express/handler/express.go`

#### 核心功能

1. **List** - 列表查询
   - 支持按编码、名称模糊查询
   - 支持分页
   - 按排序号升序排列
   
2. **Get** - 获取详情
   - 按ID查询单个快递公司
   - 返回完整信息

3. **Create** - 创建
   - 验证必填字段（名称）
   - 编码为空时自动生成
   - 返回创建的对象

4. **Update** - 更新
   - 验证快递公司存在性
   - 更新所有可修改字段
   - 编码唯一性由Model层验证

5. **Delete** - 删除
   - 软删除
   - Schema隔离确保安全性

6. **Comp** - 组件数据
   - 返回启用状态的快递公司
   - 用于下拉选择等组件
   - 限制100条

#### 技术实现

```go
func (h *ExpressHandler) List(c *gin.Context) {
    // 1. 从context获取租户DB
    db, err := middleware.GetTenantDB(c)
    
    // 2. 绑定查询参数
    var req api.ReqListExpress
    c.ShouldBindQuery(&req)
    
    // 3. 构建查询（模糊查询、分页）
    query := db.Model(&model.Express{})
    if req.Code != "" {
        query = query.Where("code LIKE ?", "%"+req.Code+"%")
    }
    
    // 4. 查询总数和数据
    var total int64
    query.Count(&total)
    var expressList []model.Express
    query.Offset(offset).Limit(limit).Find(&expressList)
    
    // 5. 转换为DTO并返回
    c.JSON(http.StatusOK, api.RespListExpress{...})
}
```

**关键点**:
- ✅ 从context获取租户DB（不存储DB实例）
- ✅ Schema隔离确保多租户安全
- ✅ 直接使用GORM操作数据库
- ✅ Model层BeforeSave/BeforeUpdate处理业务逻辑
- ✅ DTO转换隔离内部模型和外部API

### 3.3 路由注册

**文件**: `internal/express/router.go`

```go
func InitRouter(r *gin.RouterGroup, db *gorm.DB) {
    expressHandler := handler.NewExpressHandler(db)
    
    express := r.Group("/express")
    {
        express.GET("", expressHandler.List)         // GET /api/v1/express
        express.POST("", expressHandler.Create)      // POST /api/v1/express
        express.GET("/comp", expressHandler.Comp)    // GET /api/v1/express/comp
        express.GET("/:id", expressHandler.Get)      // GET /api/v1/express/:id
        express.PUT("/:id", expressHandler.Update)   // PUT /api/v1/express/:id
        express.DELETE("/:id", expressHandler.Delete)// DELETE /api/v1/express/:id
    }
}
```

**注意事项**:
- `/comp`路由放在`/:id`之前，避免路由冲突
- 所有路由都在`/express`组下
- 完整路径为`/api/v1/express/*`

| 业务验证 | 分散在Biz/Store层 | 集中在Model层 | 更清晰 |

## 6. 技术亮点

### 6.1 Schema级多租户

- ✅ Handler从context获取已切换schema的DB

- ✅ 数据库层面保证隔离性
- ✅ 防止跨租户数据访问

- ✅ 减少不必要的抽象层
- ✅ Handler直接操作数据库
- ✅ Model层处理业务逻辑
