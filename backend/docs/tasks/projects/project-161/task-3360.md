# 商品模块API设计文档（Swagger）

## 文档信息

**项目名称**: Coolbuy 3.0 - 商品管理模块  
**API版本**: v1  
**Base URL**: `http://localhost:7091/api/v1`  
**认证方式**: JWT Bearer Token  
**多租户支持**: 通过 `X-Tenant-ID` Header

---

## 认证说明

所有API请求都需要包含以下Headers：

```http
Authorization: Bearer {JWT_TOKEN}
X-Tenant-ID: {TENANT_ID}
Content-Type: application/json
```

---

## API模块概览

商品模块包含12个子模块，共计100+个API接口：

| 模块 | 路由前缀 | 接口数 | 说明 |
|------|---------|--------|------|
| 分类管理 | `/categories` | 9 | 商品分类树形结构管理 |
| 品牌管理 | `/brands` | 6 | 品牌信息管理 |
| 单位管理 | `/units` | 7 | 计量单位及换算 |
| 产品标签 | `/product-tags` | 7 | SPU标签分类管理 |
| SPU管理 | `/spus` | 10 | 标准产品单元管理 |
| SPU区域 | `/spu-areas` | 7 | SPU地区销售配置 |
| SPU批次 | `/spu-batches` | 7 | SPU批次管理 |
| SKU管理 | `/skus` | 6 | 库存单元管理 |
| 属性组 | `/attribute-groups` | 8 | 商品属性分组 |
| 属性定义 | `/attributes` | 8 | 商品属性定义 |
| 属性值 | `/attribute-values` | 10 | SPU属性值管理 |
| 规格组 | `/spec-groups` | 7+ | SKU规格管理 |

## 1. 分类管理 API

### 1.1 分类列表

```
GET /api/v1/categories
```

**Query Parameters**:
- `page` (int): 页码，默认1
- `page_size` (int): 每页数量，默认20
- `parent_id` (int): 父分类ID筛选
- `status` (int): 状态筛选
- `name` (string): 名称模糊搜索

**Response**:
```json
{
  "count": 100,
  "data": [
    {
      "id": 1,
      "name": "运动鞋",
      "parent_id": null,
      "sort": 1,
      "status": 1,
      "path": "/1/",
      "level": 0,
      "product_count": 1200,
      "created_at": "2025-11-06T10:00:00Z",
      "updated_at": "2025-11-06T10:00:00Z"
    }
  ]
}
```

### 1.2 获取分类树

```
GET /api/v1/categories/tree
```

**Response**:
```json
{
  "data": [
    {
      "id": 1,
      "name": "运动鞋",
      "children": [
        {
          "id": 2,
          "name": "跑步鞋",
          "children": []
        }
      ]
    }
  ]
}
```

### 1.3 获取分类详情

```
GET /api/v1/categories/:id
```

### 1.4 获取子分类

```
GET /api/v1/categories/:id/children
```

### 1.5 获取分类路径

```
GET /api/v1/categories/:id/path
```

**Response**:
```json
{
  "data": [
    {"id": 1, "name": "运动鞋"},
    {"id": 2, "name": "跑步鞋"},
    {"id": 3, "name": "专业跑鞋"}
  ]
}
```

### 1.6 创建分类

```
POST /api/v1/categories
```

**Request Body**:
```json
{
  "name": "篮球鞋",
  "parent_id": 1,
  "sort": 1,
  "status": 1
}
```

### 1.7 更新分类

```
PUT /api/v1/categories/:id
```

### 1.8 移动分类

```
PUT /api/v1/categories/:id/move
```

**Request Body**:
```json
{
  "new_parent_id": 2,
  "sort": 1
}
```

### 1.9 更新排序

```
PUT /api/v1/categories/:id/sort
```

**Request Body**:
```json
{
  "sort": 5
}
```

### 1.10 删除分类

```
DELETE /api/v1/categories/:id
```

## 错误码说明

### HTTP状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 请求成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未授权（Token无效或过期） |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 业务错误响应格式

```json
{
  "error": "错误描述信息"
}
```

### 常见错误示例

```json
{
  "error": "无法获取数据库连接"
}
```

## 开发建议

### 1. 分页规范
- 默认page=1, page_size=20
- 最大page_size=100
- 使用count字段返回总数

### 2. 筛选规范
- 支持多维度组合筛选
- 字符串字段支持模糊搜索
- 数值字段支持范围筛选（min/max）

### 3. 排序规范
- 默认按updated_at降序
- 支持自定义排序字段

### 4. 软删除
- 所有删除操作均为软删除
- 使用deleted_at字段标记
- 查询时自动过滤已删除数据

### 5. 多租户隔离
- 每个请求必须包含X-Tenant-ID
- 数据库层面使用Schema隔离
- 自动注入租户上下文
