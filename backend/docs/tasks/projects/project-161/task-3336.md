## 一、模块概述

### 1.1 业务背景

Coolbuy 3.0系统（酷采）是一个B2B电商平台，主要面向李宁、百丽、波司登等鞋服品牌的多级分销体系。定价模块是整个系统的核心模块之一，负责管理和计算不同层级、不同客户的商品价格。

### 1.2 核心功能

1. **多层级定价管理**：支持平台、代理商、店铺、客户等多层级定价
2. **灵活的定价策略**：支持固定价、折扣价、毛利加价等多种定价方式
3. **品牌指导价管理**：支持品牌方设置统一的客户等级指导价
4. **客户专属定价**：支持为特定客户设置专属价格
5. **批量价格导入**：支持通过Excel批量导入和更新价格

## 三、定价策略详解

### 3.1 定价类型 (type字段)

系统支持5种定价类型，通过`type`字段标识：

| Type | 名称 | 说明 | value含义 | 计算公式 |
|------|------|------|-----------|----------|
| 1 | 固定价格 | 直接设置固定价格 | 固定价格值 | `buy_price = value` |
| 2 | 吊牌价折扣 | 按吊牌价的折扣计算 | 折扣百分比 | `buy_price = market_price × (value/100)` |
| 3 | 成本毛利加价 | 按成本价加价百分比 | 加价百分比 | `buy_price = buy_price × (value/100)` |
| 4 | 销售毛利加价 | 按销售毛利率计算 | 毛利率百分比 | `buy_price = buy_price / (value/100)` |
| 5 | 采购折扣累加 | 累加采购折扣 | 折扣百分比 | 累加计算 |

### 3.3 价格计算优先级

系统在计算商品价格时，遵循以下优先级：

1. **客户专属定价** (cool_customer_price) - 最高优先级
2. **级别定价** (cool_level_price) - 中等优先级
3. **品牌指导价** (biz_client_guide_price_detail) - 较低优先级
4. **统一定价** (SKU表中的固定价格) - 最低优先级

4. **价格计算策略**
   - 查询客户专属定价
   - 若无，查询级别定价

#### 10.2.6 缓存设计 (Redis)

**缓存Key设计**:

```
# SKU价格缓存
price:sku:{sku_id}:{company_id}:{level_id}

Value: {"price": 300.00, "type": "level_price", "discount": 60}

# 价格模板缓存
price:template:{brand_id}:{level_code}
TTL: 3600秒 (1小时)

# 客户等级缓存

# 价格计算锁
lock:price:calculate:{sku_id}
TTL: 10秒
Value: "locked"
```

**缓存更新策略**:

1. **Cache Aside Pattern** (旁路缓存)
   - 查询时先查缓存，缓存miss则查数据库并回写
   - 更新时先更新数据库，再删除缓存

2. **主动失效**
   - 价格更新后主动清除相关缓存
   - 使用Redis Pipeline批量删除

3. **预热机制**
   - 系统启动时预热热门SKU价格
   - 定时任务刷新高频查询的价格

package pricing

import (
    "context"
    "encoding/json"

    "time"

type PricingCache struct {
    rdb *redis.Client
}

// 获取SKU价格（带缓存）
func (c *PricingCache) GetSkuPrice(ctx context.Context, skuID, companyID, levelID string) (*Price, error) {
    // 1. 构造缓存key
    cacheKey := fmt.Sprintf("price:sku:%s:%s:%s", skuID, companyID, levelID)
    
    // 2. 尝试从缓存获取
    val, err := c.rdb.Get(ctx, cacheKey).Result()
    if err == nil {
        var price Price
        if err := json.Unmarshal([]byte(val), &price); err == nil {
            return &price, nil
        }
    }
    
    // 3. 缓存miss，从数据库查询
    price, err := c.calculatePriceFromDB(ctx, skuID, companyID, levelID)
    if err != nil {
        return nil, err
    }
    
    // 4. 写入缓存
    data, _ := json.Marshal(price)
    c.rdb.Set(ctx, cacheKey, data, 30*time.Minute)
    
    return price, nil
}

// 批量获取价格（使用Pipeline）
func (c *PricingCache) BatchGetPrices(ctx context.Context, skuIDs []string, companyID, levelID string) ([]*Price, error) {
    pipe := c.rdb.Pipeline()
    
    // 构造所有缓存key
    cacheKeys := make([]string, len(skuIDs))
    for i, skuID := range skuIDs {
        cacheKeys[i] = fmt.Sprintf("price:sku:%s:%s:%s", skuID, companyID, levelID)
    }
    
    // 批量查询
    cmds := make([]*redis.StringCmd, len(cacheKeys))
    for i, key := range cacheKeys {
        cmds[i] = pipe.Get(ctx, key)
    }
    
    _, err := pipe.Exec(ctx)
    if err != nil && err != redis.Nil {
        return nil, err
    }
    
    // 处理结果
    prices := make([]*Price, len(skuIDs))
    missIndexes := []int{}
    
    for i, cmd := range cmds {
        val, err := cmd.Result()
        if err == redis.Nil {
            missIndexes = append(missIndexes, i)
            continue
        }
        
        var price Price
        if err := json.Unmarshal([]byte(val), &price); err == nil {
            prices[i] = &price
        } else {
            missIndexes = append(missIndexes, i)
        }
    }
    
    // 处理缓存miss的数据
    if len(missIndexes) > 0 {
        missSkuIDs := make([]string, len(missIndexes))
        for i, idx := range missIndexes {
            missSkuIDs[i] = skuIDs[idx]
        }
        
        // 批量查询数据库
        missedPrices, err := c.batchCalculatePricesFromDB(ctx, missSkuIDs, companyID, levelID)
        if err != nil {
            return nil, err
        }
        
        // 回写缓存并填充结果
        for i, price := range missedPrices {
            idx := missIndexes[i]
            prices[idx] = price
            
            // 异步写入缓存
            go func(p *Price, skuID string) {
                data, _ := json.Marshal(p)
                key := fmt.Sprintf("price:sku:%s:%s:%s", skuID, companyID, levelID)
                c.rdb.Set(context.Background(), key, data, 30*time.Minute)
            }(price, missSkuIDs[i])
        }
    }
    
    return prices, nil
}

// 删除价格缓存
func (c *PricingCache) InvalidateSkuPrice(ctx context.Context, skuID string) error {
    // 删除所有相关的价格缓存
    pattern := fmt.Sprintf("price:sku:%s:*", skuID)
    
    iter := c.rdb.Scan(ctx, 0, pattern, 0).Iterator()
    pipe := c.rdb.Pipeline()
    
    for iter.Next(ctx) {
        pipe.Del(ctx, iter.Val())
    }
    
    if err := iter.Err(); err != nil {
        return err
    }
    
    _, err := pipe.Exec(ctx)
    return err
}

// 预热热门商品价格
func (c *PricingCache) WarmupHotPrices(ctx context.Context, hotSkuIDs []string) error {
    // 获取所有活跃公司
    companies, err := c.getActiveCompanies(ctx)
    if err != nil {
        return err
    }
    
    // 为每个公司预热热门SKU的价格
    for _, company := range companies {
        for _, skuID := range hotSkuIDs {
            price, err := c.calculatePriceFromDB(ctx, skuID, company.ID, company.LevelID)
            if err != nil {
                continue  // 忽略单个商品的错误
            }
            
            cacheKey := fmt.Sprintf("price:sku:%s:%s:%s", skuID, company.ID, company.LevelID)
            data, _ := json.Marshal(price)
            c.rdb.Set(ctx, cacheKey, data, 30*time.Minute)
        }
    }
    
    return nil
}

// 使用sync.Map减少锁竞争
type PriceCache struct {
    cache sync.Map  // key: string, value: *CachedPrice
}

type CachedPrice struct {
    Price      *Price
    ExpireTime time.Time
    mu         sync.RWMutex
}

func (c *PriceCache) Get(key string) (*Price, bool) {
    val, ok := c.cache.Load(key)
    if !ok {
        return nil, false
    }
    
    cached := val.(*CachedPrice)
    cached.mu.RLock()
    defer cached.mu.RUnlock()
    
    if time.Now().After(cached.ExpireTime) {
        return nil, false
    }
    
    return cached.Price, true
}

// 使用分组锁减少锁粒度
type ShardedPriceCache struct {
    shards []*PriceCacheShard
    mask   uint32
}

type PriceCacheShard struct {
    mu    sync.RWMutex
    cache map[string]*Price
}

func (c *ShardedPriceCache) getShard(key string) *PriceCacheShard {
    hash := fnv.New32()
    hash.Write([]byte(key))
    return c.shards[hash.Sum32()&c.mask]
}

// 价格导入异步处理
type PriceImportProcessor struct {
    taskQueue chan *ImportTask
    workers   int
}

func (p *PriceImportProcessor) Start() {
    for i := 0; i < p.workers; i++ {
        go p.worker()
    }
}

func (p *PriceImportProcessor) worker() {
    for task := range p.taskQueue {
        p.processImportTask(task)
    }
}

func (p *PriceImportProcessor) processImportTask(task *ImportTask) {
    // 批量处理
    const batchSize = 1000
    
    for i := 0; i < len(task.Rows); i += batchSize {
        end := i + batchSize
        if end > len(task.Rows) {
            end = len(task.Rows)
        }
        
        batch := task.Rows[i:end]
        p.processBatch(batch)
    }
}

### B. 常见问题FAQ

**Q1: 为什么价格计算这么复杂？**

A: Coolbuy系统面向鞋服行业的多级分销体系，需要支持品牌方、一批、二批、三批等多层级定价，同时要兼容不同品牌的定价规则（如李宁的特殊规则）。

**Q2: 价格更新后多久生效？**

A: 立即生效。但由于缓存机制，可能需要等待缓存过期（最长30分钟）才能看到新价格。建议重要价格更新后手动清除缓存。

**Q3: 如何保证价格计算的准确性？**

A: 系统使用BigDecimal进行所有价格计算，避免浮点数精度问题。同时有完善的数据校验和异常处理机制。

**Q4: 批量导入价格时性能如何？**

A: 系统使用异步批量处理，单次可处理数万条数据。建议单次导入不超过10万条，过大的数据量建议分批导入。
