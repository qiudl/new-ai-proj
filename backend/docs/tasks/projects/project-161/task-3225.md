## 🤔 为什么Bundle大小没变化？

### Tree-shaking已经生效

Vite/Rollup的**tree-shaking**机制会自动移除未被import的代码：

1. **ahooks, classnames, lodash-es** - 虽然在package.json中，但代码中从未import
2. **Tree-shaking** - 构建时自动排除，不会打包进bundle
3. **移除依赖的好处** - 减少node_modules大小，清理项目结构，但不影响bundle大小

## 🔍 vendor-misc组成分析

### 主要组成部分

根据vite.config.ts的manualChunks逻辑分析：

```typescript
// vendor-misc包含所有未被其他规则匹配的node_modules依赖
// 其他第三方库
return 'vendor-misc'
```

**主要内容**:

1. **echarts** (~600-700 KB)
   - 图表库核心
   - @ant-design/charts的依赖
   - 虽然使用React.lazy()懒加载，但因componentMap静态导入被preload

2. **@antv系列** (~200-300 KB)
   - @antv/g2, @antv/g2plot等
   - @ant-design/charts的依赖
   - 数据可视化引擎

3. **quill** (~200 KB)
   - react-quill的依赖
   - 富文本编辑器核心
   - 被ContentEditor使用，也因componentMap静态导入被preload

4. **其他依赖** (~200-300 KB)
   - 各种小型工具库和polyfills

### 为什么这些库在vendor-misc？

**Vite配置分析** (vite.config.ts:113-121):

```typescript
// UI库规则匹配antd和@ant-design
if (id.includes('antd') || id.includes('@ant-design')) {
  return 'vendor-ui'  // @ant-design/charts进入vendor-ui
}

// 图表库规则被注释(为了支持懒加载)
// if (id.includes('echarts') || id.includes('@antv')) {
//   return 'vendor-charts'
// }

// 其他第三方库默认进vendor-misc
return 'vendor-misc'  // echarts、@antv、quill进入这里
```

**结论**: echarts和@antv虽然是图表相关，但不包含'@ant-design'字符串，所以进入vendor-misc而非vendor-ui
