# 商品模块数据库Schema设计文档

## 1. 概述

### 1.1 设计目标

本文档描述了Coolbuy 3.0商品模块的完整数据库Schema设计，采用SPU/SKU两层产品结构，支持:

- **多租户架构**: 通过PostgreSQL Schema隔离实现数据隔离
- **ERP集成**: 完整的ERP字段映射，支持李宁、百丽、波司登等品牌
- **灵活属性系统**: 支持规格属性、非规格属性、属性模板
- **层级分类**: 树形分类结构，支持无限层级
- **批次管理**: 支持产品批次、地区上市信息
- **图片管理**: 主图、详情图分类管理

### 1.2 核心设计原则

1. **Schema隔离**: 使用PostgreSQL Schema (public, tenant_1, tenant_2...) 实现租户数据隔离
2. **软删除**: 所有核心表使用deleted_at字段实现软删除
3. **审计字段**: 标准的created_at, updated_at时间戳
4. **索引优化**: 为高频查询字段建立索引
5. **外键约束**: 使用ON DELETE CASCADE保证数据一致性

| name | VARCHAR(200) | - | NOT NULL | SKU名称 |
| size | VARCHAR(50) | - | - | 尺码 |
| color | VARCHAR(100) | - | - | 颜色 |
| style_number | VARCHAR(100) | INDEX | - | 款号 |
| eanupc | VARCHAR(50) | INDEX | - | EAN/UPC条码 |
| market_price | DECIMAL(10,2) | - | NOT NULL | 市场价 |
| cost_price | DECIMAL(10,2) | - | - | 成本价 |
| member_price | DECIMAL(10,2) | - | - | 会员价 |
| stock | INT | INDEX | NOT NULL | 当前库存 |
| stock_alert_threshold | INT | - | - | 库存预警阈值 |
| stock_max_threshold | INT | - | - | 最大库存阈值 |
| warehouse_location | VARCHAR(100) | - | - | 仓库位置 |
| weight | DECIMAL(10,2) | - | - | 重量(克) |
| length | DECIMAL(10,2) | - | - | 长(cm) |
| width | DECIMAL(10,2) | - | - | 宽(cm) |
| height | DECIMAL(10,2) | - | - | 高(cm) |
| enabled | BOOLEAN | - | NOT NULL | 启用状态 |
| created_at | TIMESTAMP | - | - | 创建时间 |
| updated_at | TIMESTAMP | - | - | 更新时间 |
| deleted_at | TIMESTAMP | INDEX | - | 软删除时间 |

#### 唯一约束

```sql
UNIQUE INDEX idx_skus_code ON skus(code);
-- 同一SPU下，尺码+颜色组合唯一
UNIQUE INDEX idx_skus_spu_size_color ON skus(spu_id, size, color) WHERE deleted_at IS NULL;
```

#### 关联关系

```go
Spu *Spu `foreignKey:SpuID` // 所属SPU
```

## 8. 多租户架构

### 8.1 Schema隔离策略

每个租户使用独立的PostgreSQL Schema:

```
public          -- 系统公共表
tenant_1        -- 租户1数据
tenant_2        -- 租户2数据
tenant_N        -- 租户N数据
```

### 8.2 数据隔离

**模型层面** (GORM):
```go
// 多租户通过PostgreSQL Schema隔离，无需TenantID字段
type Spu struct {
    ID   uint   `gorm:"primaryKey"`
    Code string `gorm:"uniqueIndex"` // 在Schema内唯一
    // ... 不包含TenantID字段
}
```

**中间件层面**:
```go
// 从请求Header获取租户ID
tenantID := c.GetHeader("X-Tenant-ID")

// 切换到租户Schema
db := db.Exec("SET search_path TO tenant_" + tenantID)
```

### 8.3 迁移策略

每个SQL迁移文件需要同时创建:
1. `public` schema的表 (系统表)
2. `tenant_1` schema的表 (示例租户)

```sql
-- Public Schema
CREATE TABLE public.spus (...);

-- Tenant Schema  
CREATE TABLE tenant_1.spus (...);
```

## 11. 数据一致性保证

### 11.1 外键约束

```sql
-- SPU → 分类
ALTER TABLE spus 
ADD CONSTRAINT fk_spus_category 
FOREIGN KEY (category_id) REFERENCES categories(id);

-- SKU → SPU (级联删除)
ALTER TABLE skus 
ADD CONSTRAINT fk_skus_spu 
FOREIGN KEY (spu_id) REFERENCES spus(id) 
ON DELETE CASCADE;

-- SPU图片 → SPU (级联删除)
ALTER TABLE spu_images 
ADD CONSTRAINT fk_spu_images_spu 
FOREIGN KEY (spu_id) REFERENCES spus(id) 
ON DELETE CASCADE;

-- 属性值 → 属性 (级联删除)
ALTER TABLE spu_attribute_values 
ADD CONSTRAINT fk_attr_values_attr 
FOREIGN KEY (attribute_id) REFERENCES attributes(id) 
ON DELETE CASCADE;
```

### 11.2 唯一性约束

```sql
-- SPU编码全局唯一
ALTER TABLE spus ADD CONSTRAINT uk_spus_code UNIQUE (code);

-- SKU编码全局唯一
ALTER TABLE skus ADD CONSTRAINT uk_skus_code UNIQUE (code);

-- 同一SPU下size+color唯一
```

## 12. 性能优化建议

### 12.1 查询优化

1. **分页查询**: 使用LIMIT/OFFSET，避免一次性加载大量数据
   ```sql
   SELECT * FROM spus 
   WHERE deleted_at IS NULL 
   ORDER BY id DESC 
   LIMIT 20 OFFSET 0;
   ```

2. **条件筛选**: 优先使用索引字段
   ```sql
   -- 好: 使用索引字段
   SELECT * FROM spus WHERE brand_id = 1 AND enabled = true;
   
   -- 差: 使用非索引字段
   SELECT * FROM spus WHERE description LIKE '%鞋%';
   ```

3. **关联查询**: 使用JOIN代替子查询
   ```sql
   -- 好: JOIN查询
   SELECT s.*, b.brand_name 
   FROM spus s 
   LEFT JOIN brands b ON s.brand_id = b.id;
   
   -- 差: 子查询
   SELECT *, (SELECT brand_name FROM brands WHERE id = spus.brand_id) 
   FROM spus;
   ```

### 12.2 索引维护

1. **定期分析表**: 更新统计信息
   ```sql
   ANALYZE spus;
   ANALYZE skus;
   ```

2. **重建索引**: 清理索引碎片
   ```sql
   REINDEX TABLE spus;
   REINDEX TABLE skus;
   ```

3. **监控索引使用**: 删除未使用的索引
   ```sql
   SELECT * FROM pg_stat_user_indexes WHERE idx_scan = 0;
   ```

### 12.3 分区策略

对于大数据量场景，可以考虑分区:

```sql
-- 按年份分区SPU表
CREATE TABLE spus_2024 PARTITION OF spus 
FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');

CREATE TABLE spus_2025 PARTITION OF spus 
FOR VALUES FROM ('2025-01-01') TO ('2026-01-01');
```

## 14. 注意事项

### 14.1 字段命名规范

- 使用snake_case命名法
- 时间字段统一使用_at后缀: `created_at`, `updated_at`, `deleted_at`
- 布尔字段使用is_前缀或enabled: `is_default`, `enabled`
- 关联ID字段使用_id后缀: `spu_id`, `category_id`

### 14.2 软删除实现

所有核心业务表使用软删除:
```go
DeletedAt gorm.DeletedAt `gorm:"index" json:"-"`
```

查询时需要过滤已删除记录:
```sql
WHERE deleted_at IS NULL
```

### 14.3 ERP字段管理

SPU表包含大量ERP同步字段(100+个):
- 不是所有字段都必填
- 字段值由ERP系统同步更新
- 自建商品可能只填写核心字段

### 14.4 Schema同步

新增表或修改表结构时:
1. 先修改模型文件 (model/*.go)
2. 创建迁移文件 (migrations/*.sql)
3. 同时更新public和tenant_1 schema
4. 测试迁移的up和down脚本
