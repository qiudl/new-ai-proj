## 🐛 发现的Bug详情

### Bug #1: Token认证格式不稳定 (高优先级)
- **描述**: Bearer Token认证在不同API调用间出现格式错误
- **重现步骤**: 
  1. 成功登录获取token
  2. 调用计时器相关API
  3. 间隔调用时出现"Authorization header must start with 'Bearer '"错误
- **预期行为**: Token在有效期内应持续工作
- **实际行为**: Token格式验证不一致，导致部分API调用失败
- **影响程度**: 高 - 严重影响用户使用计时器功能

### Bug #2: 项目任务计时器标题验证失败 (高优先级)  
- **描述**: 启动项目任务计时器时提示"计时器标题不能为空"
- **重现步骤**:
  1. 使用有效token调用 /api/v1/user/timer/start
  2. 传入参数: {"task_id": 168, "auto_stop_others": true}
  3. 返回错误: "计时器标题不能为空"
- **预期行为**: 项目任务应自动获取任务标题用于计时器
- **实际行为**: 无法获取任务标题，启动失败
- **影响程度**: 高 - 项目任务计时器完全无法使用
- **对比测试**: 个人计时器(传入title参数)可以正常启动

### Bug #3: 计时器操作链条中断 (中优先级)
- **描述**: 成功启动个人计时器后，无法进行后续操作(暂停/恢复/停止)
- **重现步骤**:
  1. 成功启动个人计时器 (返回success: true)
  2. 尝试调用暂停API: /api/v1/user/timer/pause
  3. 返回认证错误，无法继续操作
- **预期行为**: 启动后应能正常暂停、恢复、停止
- **实际行为**: 只能启动，无法进行任何后续操作
- **影响程度**: 中 - 计时器功能链条不完整
