# Dev Plans - 任务文档开发计划目录

## 📋 目录说明

本目录用于存储 **ai-proj 系统中的任务文档导出文件**，专门为 **Claude Code 网页版**提供在线 coding 时的上下文支持。

## 🎯 核心目标

实现任务文档的**双重管理模式**：
- ✅ 数据库存储：通过 ai-proj 系统完整的任务管理功能
- ✅ 文件系统访问：供 Claude Code 网页版读取完整的开发上下文

## 📁 文件命名规范

```
{task_id}_{task_title}.md
```

### 示例：
- `3653_用户模型enterprise_id支持.md`
- `3672_任务文档文件系统同步.md`
- `3674_实现任务文档导出为文件的核心逻辑.md`

### 命名规则：
1. **task_id**：任务在数据库中的唯一标识
2. **task_title**：任务标题（简化版，去除特殊字符）
3. **后缀**：统一使用 `.md`（Markdown 格式）

## 📄 文档内容结构

每个任务文档包含以下标准章节：

```markdown

- 任务ID：#xxxx

- 状态：进行中/已完成/待处理

- 预计工时：X 小时

## 📝 任务描述
[任务的详细描述]

## 🎯 目标与范围
[明确的目标和实现范围]

## 💡 技术方案
### 方案概述
### 实现步骤
### 技术选型

## 📋 开发计划
- [ ] 步骤1
- [ ] 步骤2
- [ ] 步骤3

## ✅ 验收标准
- [ ] 标准1

## 📚 参考资料
[相关文档链接]

```

## 🔄 同步机制

### 自动同步（推荐）
任务文档在数据库中创建或更新时，自动导出到本目录：
```
数据库任务文档 → 自动导出 → docs/dev-plans/{task_id}_{title}.md
```

### 手动同步
通过 MCP 接口手动触发同步：

```javascript
// 导出单个任务文档
mcp__ai-proj__export_task_document_to_file({ taskId: 3672 })

// 从文件导入更新
mcp__ai-proj__import_task_document_from_file({ taskId: 3672 })

// 批量同步
mcp__ai-proj__sync_task_documents({ projectId: 1 })
```

## 🚀 Claude Code 网页版使用流程

### 1. 开始任务
```bash
# Claude Code 读取任务文档
Read: backend/docs/dev-plans/3672_任务文档文件系统同步.md
```

### 2. 开发过程
- 查看完整的任务需求、技术方案、开发计划
- 所有上下文信息都在文件中，无需反复查询数据库
- 可以直接在文档中标注进度

### 3. 完成后同步
```bash
# 将更新后的文档同步回数据库
mcp__ai-proj__import_task_document_from_file({ taskId: 3672 })
```

## 🔧 维护指南

### 目录清理
定期清理已完成任务的文档（可选）：
```bash
# 归档已完成任务
mv 3672_*.md ../archives/2025-11/
```

### 版本控制
- 所有文档文件纳入 Git 版本控制
- 重要节点创建 Git tag
- 使用 `.gitignore` 排除临时文件

### 权限管理
- 目录权限：`755` (drwxr-xr-x)
- 文件权限：`644` (-rw-r--r--)
- 确保后端服务有读写权限

## 🔐 安全注意事项

1. **敏感信息**：不要在文档中直接写入密码、密钥等敏感信息
2. **权限控制**：确保目录权限正确，防止未授权访问
3. **备份策略**：定期备份重要任务文档

## 📈 性能优化

1. **延迟同步**：使用队列异步处理文档导出
2. **增量同步**：只同步变更的文档
3. **缓存策略**：缓存常用文档的读取结果

## 🆘 故障排查

### 问题：文档未自动生成
- 检查后端服务日志
- 验证文档导出钩子是否正常工作
- 确认目录权限

### 问题：文档内容不同步
- 检查最后同步时间戳
- 手动触发同步接口
- 对比数据库和文件内容

### 问题：Claude Code 无法读取
- 确认文件路径正确
- 检查文件权限
- 验证文件格式（UTF-8 编码）
