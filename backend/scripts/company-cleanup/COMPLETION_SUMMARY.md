### 1. 系统调研和分析 ✅

#### 1.1 数据库调研

调研了company体系在数据库中的完整使用情况：

**Company体系表结构**:
- `companies` - 2条记录（企业基本信息）
- `customers` - 6条记录（客户信息）
- `company_users` - 8个用户
- `company_departments` - 0条记录
- `company_roles` - 角色定义
- `company_user_project_permissions` - 项目权限
- `project_companies` - 项目关联

**Enterprise体系表结构**:
- `enterprises` - 2条记录
- `enterprise_users` - 9个用户

#### 1.2 问题识别

发现的核心问题：
1. **重复用户**: akang和litingting同时存在于两个体系
2. **数据冗余**: 两套并行的企业管理系统
3. **逻辑混乱**: 代码需要同时处理两种类型
4. **维护困难**: 功能更新需要双重实现

#### 1.3 架构分析

对比分析结果：
- Enterprise体系架构更完善
- Enterprise有更灵活的权限管理（access_level）
- Enterprise用户数更多（9 vs 8）
- Company体系是历史遗留

**决策**: 保留Enterprise体系，清理Company体系

### 4. 设计决策和方案 ✅

#### 4.1 迁移策略

采用**渐进式迁移**:
```
备份 → 迁移 → 验证 → 清理 → 代码更新
```

**优点**:
- 每步可验证
- 支持回滚
- 风险可控
- 可追溯

#### 4.2 重复用户处理策略

**问题**: akang和litingting同时存在于company和enterprise
**方案**: 保留enterprise用户，将company用户重命名为 `username_company`

**SQL实现**:
```sql
UPDATE users u1
SET username = u1.username || '_company'
WHERE u1.user_type = 'company'
  AND EXISTS (
      SELECT 1 FROM users u2
      WHERE u2.username = u1.username
        AND u2.user_type = 'enterprise'
  );
```

#### 4.3 回滚方案

设计了3种回滚方案：
1. **完整备份恢复** - 适用于严重问题
2. **SQL备份恢复** - 恢复特定表
3. **软删除回滚** - 快速恢复（仅软删除模式）

#### 4.4 约束更新策略

**更新CHECK约束**:
```sql
-- user_type约束：移除'company'
ALTER TABLE users ADD CONSTRAINT users_user_type_check
    CHECK (user_type IN ('system', 'enterprise'));

-- role约束：移除company相关角色
ALTER TABLE users ADD CONSTRAINT users_role_check
    CHECK (role IN ('admin', 'user', 'enterprise_admin', 'enterprise_user'));
```
